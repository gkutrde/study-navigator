# 学习领航员（Study Navigator）

把「飞书抄笔记」变成「学完就动手做」的**本地**学习闭环工具。

它读你的飞书笔记（含子文档）与 DeepSeek 书籍蒸馏稿，维护两份档案：

- **知识画像**（`profile/knowledge.md`）：我会什么 —— 每个知识点带「学过 / 做过 / 输出 / 存疑」四态与证据
  （**输出** = 能用自己的话讲清楚，也就是费曼复述）；
- **知识地图**（`profile/syllabus.md`）：这本书还有什么该学 —— 书名 → 章节 → 知识点。

然后基于两者生成一个**现在就能动手做**的小任务（含目标与验收方式），做完回写画像，形成 学 → 练 → 复盘 的循环。

> 写代码的是你，不是工具。工具只负责「读懂笔记 → 判断你会什么 → 安排下一步练什么」。

## 快速开始

### 0. 环境要求

- Python 3.11 以上（开发验证用的是 3.12 / 3.14）
- 第三方依赖只有两个：`requests`（飞书接口）、`pytest`（跑测试，可选）
- 飞书自建应用（见下）与 LLM 额度（Kimi Code 会员 或 DeepSeek Key）

安装依赖：

    python -m pip install requests
    python -m pip install pytest        # 只有想跑测试时才需要

### 1. 配置凭证（`.env`）

复制 `.env.example` 为 `.env`，按需填写。**`.env` 已在 `.gitignore` 里，永不进仓库。**

    # 飞书自建应用（必填）
    FEISHU_APP_ID=cli_xxxxxxxxxxxxxxxx
    FEISHU_APP_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
    # 可选：学习库根节点 —— 填了它，看板「同步飞书笔记」按钮会同步整棵树
    FEISHU_ROOT_DOC=

    # LLM：默认 Kimi Code 会员（coding plan），备用 DeepSeek
    LLM_PROVIDER=kimi
    KIMI_API_KEY=            # 用 Kimi Code 会员时填（Kimi Code 控制台创建）
    # MOONSHOT_API_KEY=      # 用 Kimi 开放平台按量时填（不同平台，Key 不通用）
    DEEPSEEK_API_KEY=        # 备用 provider

**Kimi 也可以不填 Key**：工具会复用 **Kimi Code CLI 的登录态**（`~/.kimi-code/credentials/kimi-code.json`）。
只要你在 Kimi Code CLI 里 `/login` 过即可；登录态过期时会提示你重新登录（工具不会自动刷新）。

> [!注意] 截图位
> 飞书开放平台「应用身份权限」页面与「API Key」页面的截图放这里（截图里不要露出完整 Key）：
> `项目文档/assets/凭证-飞书应用权限.png`、`项目文档/assets/凭证-LLM-Key.png`

### 2. 开通飞书应用权限（必做，否则报 `99991672`）

去飞书开放平台 → 你的自建应用 → 权限管理，开通并**发布**：

| 用途 | 需要开通的权限 |
| --- | --- |
| 读文档正文 | `docx:document:readonly` |
| 解析 wiki 节点 | `wiki:node:read` |
| 列举子节点（推荐） | `wiki:node:retrieve` |

最后一项**强烈建议开**：不开也能用（工具会退化为「从父文档的文档提及里发现子文档」，实测可覆盖），
但开了才能拿到真实的子文档层级。另外记得把目标文档**分享给应用**，否则仍会无权限。

### 3. 跑通一次闭环

    python -m src.cli sync https://<你的租户>.feishu.cn/wiki/<wiki节点token>   # 同步（含子文档）
    python -m src.cli distill --all                                            # 全量提炼 → 知识画像
    python -m src.cli next                                                     # 出题
    # ……你自己写代码完成任务……
    python -m src.cli done 列表 tasks/wordcount.py                              # 回写画像

四步之后，`profile/knowledge.md` 里对应知识点会从「学过」变成「做过」，并附上产出路径。

## 六个命令

| 命令 | 用途 |
| --- | --- |
| `sync` | 拉取飞书文档（含全部子文档递归）为本地 markdown |
| `import` | 把 `books/` 里的蒸馏稿导入为知识地图 |
| `align` | 把地图里的点名对齐到画像概念（出题更贴合你学的东西） |
| `explain` | 讲清一个知识点：定位到书/章，取原文片段，让 LLM 讲一遍 |
| `distill` | 提炼笔记为知识点，更新知识画像 |
| `next` | 基于画像（+ 地图）生成一个动手任务 |
| `done` | 把某知识点标记为「做过」并记录产出路径 |
| `serve` | 启动本地看板（浏览器里看画像/任务，并可点按钮触发上面的动作） |

### `sync` —— 同步笔记

    python -m src.cli sync https://<你的租户>.feishu.cn/wiki/<wiki节点token>

- 支持 wiki 链接（自动先解析成文档 ID）与裸文档 ID；
- **父文档 + 全部子文档**各存一份到 `notes/<wiki节点token>.md`；
- 无权的子文档会**跳过并报出它的 ID**，其余照常拉取；
- 单篇失败不会覆盖已有文件。

### `import` —— 导入书籍蒸馏稿

把 DeepSeek 蒸馏出的 markdown 放进 `books/`，文件名即书名，顶部要有书名 frontmatter：

    ---
    title: Python 入门
    ---

    # 第 4 章 函数
    ……

然后：

    python -m src.cli import Python入门.md
    python -m src.cli align                # 把地图里的点名对齐到画像概念（可选，但强烈建议）

生成/更新 `profile/syllabus.md`（书名 → 章节 → 知识点，**不含原文段落**）。

- **长稿会分块提炼**：按 `##` 章节边界切块（上限 30000 字符），逐块调用 LLM 再合并，
  不会把整本书塞进一次调用，也不会像旧实现那样截断正文；
- 逐块打印进度（`正在提炼第 i/n 块…`）；
- 格式不符会**明确指出缺什么**（缺 frontmatter / 缺书名 / 正文为空），且既有地图不变；
- 一本书一次命令：长批量导入（如 7 本书）建议**逐本跑**，因为 Kimi 登录态约 10 分钟就过期。

### `distill` —— 提炼知识点

    python -m src.cli distill --all                    # 全量：notes/ 下所有非空笔记
    python -m src.cli distill notes/某一篇.md           # 只提炼一篇
    python -m src.cli distill --all --force            # 忽略「未变更」判定，强制全部重跑

- 逐篇打印进度：`[3/12] xxx.md — 提炼中 / 成功（N 个知识点） / 失败`；
- **跳过未变更的笔记**（按内容指纹比对 `profile/.distill-state.json`），所以重复跑很便宜；
- 单篇失败不阻塞其余，失败的篇目会明确报出原因，且**下次自动重试**；
- 有失败篇目时退出码为 1（成功的篇目照常写入画像）。

### `align` —— 命名对齐（建议导入后跑一次）

    python -m src.cli align

书里的知识点名（比如「h1 到 h6 六级标题」）和画像里的概念名（比如「标题样式」）往往对不上，
会让出题时「下一本该学什么」判断不准。`align` 用 LLM 把地图点对齐到画像概念：

- 结果写到 `profile/alignment.json`（**不动**原始 syllabus.md，也不改画像）；
- **只采信高置信度的对齐**（宁可少映射，也不把错的说成对的）；
- 之后 `next` 会自动用它选书选点：实测把「下一个该学什么」从一本**与你无关的书**的
  第一章，变成了你正在学的那本书里、**画像中状态为「存疑」**的那个知识点。

### `explain` —— 章节讲解

    python -m src.cli explain 列表
    python -m src.cli explain 列表 --refresh   # 忽略缓存，重新生成
    python -m src.cli review "2026-09-27 10:00" tasks/card.html   # 交作业换点评（按验收方式）
    python -m src.cli chat "2026-09-27 10:00" "我的代码哪里不足？"   # 终端接力：读接力上下文问 DSH

把一个知识点讲清楚：先在地图里定位它属于哪本书哪一章，再取参考文本，最后让 LLM 讲一遍。

- **参考文本优先取原书**：`books/_src/` 里有原书正文时，按蒸馏稿里 `L####–####` 标注的行号
  区间直接从 `.txt` 截取（最准确）；没有原书就退回用蒸馏稿那一章的内容；
- **单次送 LLM 的参考文本 ≤ 3000 字符**，超额自动截断并在文中注明；
- 输出会注明出处（书 · 章 · 参考的是原文还是蒸馏稿）；
- **结果会缓存**到 `profile/explanations/`：同一个知识点第二次几乎是瞬时的（零 LLM 调用），
  想重新生成加 `--refresh`；
- `name` 用**画像里的知识点名**也可以（会自动经对齐表映射到地图名）；
- **知识点不在地图里会明确报错**，不会凭空编。

### `next` —— 出题

    python -m src.cli next

- **先按画像匹配题库**：`profile/assignments.md` 收录了 CS50 / CS50P / MIT 6.0001 等公开课程的
  经典实验骨架（15 条）。命中时直接以该实验为骨架出题、**不调用 LLM**，并在结果里注明出处课程；
- **不会重复出题**：已经出过的题库条目会被跳过，LLM 路径也会带上"最近出过的任务，不要重复"；
- 没有合适的题库条目时，回退到 LLM 现编；
- 只使用画像里**已掌握**（学过/做过/输出）的知识点 + 至多 1 个新知识点；
- 「存疑」不计入已掌握：已掌握不足 3 个时会拒绝出题并提示先补笔记；
- 输出含目标、用到的知识点、实现要点、验收方式，并留档到 `profile/tasks.md`。

### `done` —— 回写

    python -m src.cli done 列表 tasks/wordcount.py
    python -m src.cli done 列表 tasks/wordcount.py --recite "列表有序可重复，用方括号创建，append 追加"

- **画像里没有这个知识点也没关系**：会自动**新增条目**（早期版本在这里报错，导致新学的点根本写不回去）；
- 不带 `--recite`：标记为「做过」，产出路径进证据；
- 带 `--recite`（**费曼复述**：用自己的话把这个知识点讲一遍）：状态升到最高态 **「输出」**，
  复述文字也进证据。讲得出来，才算真的会了。
- `done` 只升不降：已经是「输出」的知识点，再跑一次普通 done 不会被降回「做过」。
- 重复执行幂等；想显式改状态用看板的状态表单（那个可以下调）。

### `serve` —— 本地看板

python -m src.cli report [--days N]   # 周报复盘（T-044）
    python -m src.cli serve                 # 默认 http://127.0.0.1:8765/ 并自动开浏览器
    python -m src.cli serve --port 9000     # 换端口
    python -m src.cli serve --no-browser    # 不自动开浏览器

看板能做什么：

- **四个页面各司其职**：`/` 首页（概览 + 最近任务）、`/knowledge` 知识画像、`/tasks` 任务中心、`/syllabus` 知识地图；
- 顶部按钮：**同步并提炼 / 提炼知识点 / 出题 / 回写 / 讲解**（点击即执行并把结果展示在页面上）；
  「同步并提炼」是两件事一起做——客户两次踩过"点了同步、画像却没变"的坑（T-025）；
- **任务中心**：**最新的任务排在最上**；出题/回写/提交后页面会**自动滚到那张卡片**（不靠你自己翻）；
  每道任务一张卡片（时间 / 出处 / 知识点）；点知识点 chip **行内出讲解**（第二次命中缓存，毫秒级）；
  蓝色的**「提交作业」主按钮**一眼可见，可**提交作业换点评**（按这道题的验收方式给评价 + 建议，留档在卡片里，可多次提交）；也能**删除**某条任务；
- **在 DSH 中继续（弹终端）**：点这张卡片上的按钮，会生成一份接力上下文
  （`profile/handoff/<任务>.md`：任务卡 + 你提交的代码 + 画像相关点 + 书籍出处与章节 + 可粘贴的提问），
  照抄文件里的提问就能在 DSH 里接着聊。
  > 点后还会**弹一个终端窗口**自动跑 `chat`（`cmd /c start + cmd /k`），
  > 窗口保持打开可继续追问（T-036 起：弹出的窗口**直接进交互模式**，打开就自动发出首条引导提问，答完停在「你：」等你追问）；部分环境不允许弹窗时**静默降级**到下面的文字指引。
  > 本机 DSH 桌面版的 `POST /api/session/create` 需要 19387 同源的会话 cookie，而桌面版启动令牌不留磁盘副本，
  > 看板拿不到；**不会绕过鉴权**，所以这里是「生成上下文 + 手动粘贴」的降级路径。
  > 想走命令行一次性问：`dsh --profile headless "读 profile/handoff/<任务>.md，回答其中的提问"`
- **卡片下方的聊天面板**（T-034，主入口）：展开后**直接在页面里连续追问**，回答渲染回面板、不刷新、不跳滚动；
  回答渲染为**富文本**（标题/代码块/表格），思考过程以**默认折叠**块展示，回答里的项目内路径可点开（`/file`，白名单限项目目录）；**用户输入一律转义**。
  历史按任务隔离并留档到 `profile/handoff/<任务>.chat.md`；超长时保留 handoff 全文、只裁最旧轮次并注明。
  > ⚠️ **展开面板不会自动调用**：只有点了「发送」才会真跑。因为那份调用会在本机启动一个
  > `dsh --profile headless` 进程，**它能读写本项目目录**（实测它会去读仓库里的文件）。
  > 只在愿意让它看这份代码时使用。
- **出题主题**：可以只选部分主题出题（默认全选，选择记在浏览器里；一个都不选会明确报错而不是硬出题）；
- 每个知识点卡片上**点 chip 或选下拉即生效**（20ms 级、不刷新、不跳回顶部、不需要保存按钮；失败时在卡片内原地红字提示）；
- **没有 JS 也能用**：chips 不显示，改状态靠下拉 + 保存按钮（提交后回跳）；这是长期的渐进增强契约（T-026）；
- 展示三态统计、任务记录。

看板的边界（刻意如此）：

- **只有固定动作集**，页面上**没有**任何可以输入命令的地方，服务端也不会执行你输入的字符串；
- 只绑定 `127.0.0.1`，不对外网暴露；不做登录鉴权（本机自用）；
- 只读 + 受控写：除固定动作外的写请求一律 405 / 400；
- **请求来源校验**（T-050）：`Host` 必须是 `127.0.0.1` / `localhost`（挡 DNS rebinding）；
  写请求带了 `Origin` / `Referer` 就必须来自看板页面本身（挡别的网站用表单偷偷触发动作），否则 403。

## 常见问题

**Q：报 `99991672 Access denied`？**
应用身份权限没开。按上面「开通飞书应用权限」表开通后**发布**；如果报错里提到 `wiki:node:retrieve`，
说明只是缺少「列举子节点」权限，不影响使用（会自动走文档提及兜底）。

**Q：报权限错误但权限都开了？**
文档没有分享给应用。把飞书文档/知识库分享给你的自建应用（或把应用加进知识库成员）。

**Q：提示「登录态已过期，请重新登录」？**
Kimi Code 的登录态有效期较短（实测约 10 分钟级）。到 Kimi Code CLI 里重新 `/login` 即可；
工具**不会**自动刷新令牌。也可以改用 `.env` 里的 `KIMI_API_KEY`。

**Q：`next` 说「已掌握的知识点不足 3 个」？**
这是**正确**的行为 —— 不拿「存疑」的东西糊弄你。两个办法：
① 在看板里把确认掌握的改成「学过」；② 多记几篇有解释/示例的笔记再 `distill --all`。

**Q：笔记里有中文，Windows 控制台报编码错误？**
工具已把输出强制为 UTF-8。如果仍异常，先执行 `chcp 65001`，或设置环境变量 `PYTHONUTF8=1`。
读取笔记时用 `errors="replace"`，单篇编码异常不会让整批失败。

**Q：重跑 `distill --all` 会重复消耗额度吗？**
不会重复调用已提炼且内容未变的笔记（按内容指纹跳过）。想强制重跑加 `--force`。

**Q：能改知识点的名字/状态吗？**
可以，`profile/knowledge.md` 就是普通 markdown，手工编辑即可；也可以用看板的状态表单。
注意同名不同主题的条目会按**名称**区分，改状态时若名称有歧义会提示你带主题名重试。

## 安全红线

- **`.env`、`notes/`、`books/` 永不进仓库**（见 `.gitignore`）；App Secret 与 LLM Key 只存在本地。
- 凭证不进日志、不进页面、不进异常消息：报错只出现**键名**（如 `FEISHU_APP_SECRET`）、错误码与文档 ID。
- **看板没有自由命令入口**：只有固定动作集，动作名与入参都是白名单；仍只绑 `127.0.0.1`，
  并校验请求来源（别的网站不能借你的浏览器触发看板动作）。
- 每一步落盘都走「临时文件 + 替换」：失败**不会**损坏已有画像、地图或笔记副本。
- 工具对飞书是**只读**的，从不写回。
