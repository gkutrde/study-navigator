## 3. 任务A 回执的两处断言纠正

### 3.1 `title` 在不在 projcache 的显式键上？—— **在。**

任务A 正文称：「`rename` 的标题**不在** `session_projcache` 的显式 `title` 键上，而是以 storage `val` 落盘」。

实测：确切的读法路径是 **`record.rows.title.val`**，顶层确实没有 `title` 键——A 少读了一层 `rows`，所以读空后得出「不在显式键上」的结论。

```python
rec  = json.loads(path)["record"]
rec["title"]                 # KeyError / None  ← A 读的是这一层
rec["rows"]["title"]["val"]  # "T46CHAIN 任务B 1790668458796"  ← 正确的这一层
```

### 3.2 那一排「标题: None」是读法错吗？—— **不是，它们是真的没有标题。**

抽查 `session-9f664354-…`（15:34:49）：

```
rows.title     = {"val": null}
rows.titleInput= {"first": null, "count": 0, "lastSeq": null}   ← count=0
```

`titleInput.count = 0` 意味着**该会话从未收到过任何用户消息**，因此从未触发命名——不是脚本读不到，是本来就没有。
对照 `session-2677358b-…`（T46 标题测试）：`titleInput = {first:{seq:9, text:"T46B891440 讨论上下文"}, count:1}`，所以它有标题。

**给校验脚本的判别法**：

- `titleInput.count == 0` → 空会话，`title` 必为 `null`，跳过不报错；
- `titleInput.count >= 1` 且 `title.val == null` → 真正的「消息到了但没命名」，这才该报警。
