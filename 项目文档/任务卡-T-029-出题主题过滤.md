# 【T-029】 出题主题过滤

## 边界

看板主题多选（**默认全选，localStorage 记忆**）+ CLI `next --topic`（**可重复**）；
过滤作用于**画像知识池**与**新点选书范围**；**全不选明确报错不出题**。

## 修法

| 层 | 做法 |
| --- | --- |
| 工具 | `selectable_topics`（保序，「未分类」压最后）/ `normalize_topics` / `resolve_topics`（全不选 → `PlannerError`）/ `filter_profile_by_topics` |
| 出题 | `generate_task(..., topics=)`：`scoped = filter_profile_by_topics(profile, topics)`，**知识池、题库匹配、prompt、越界校验全部用 scoped** |
| 选书 | `next_unmet_point_for_books(..., topics=)`：**逐点**筛，只留落在选中主题里的点 |
| 看板 | `next` 白名单加 `topics`；主题复选框放在**表单内部**（否则不随表单提交）；JS 用 localStorage 记忆 + 全选/全不选按钮 |
| CLI | `--topic` 可重复；看板经 `topic_list` 走同一条路径 |

### 我实现时的两个错（都由测试抓出来）

1. **按"书"过滤的门槛错了**：第一版是"整本书只要有一个点匹配就留下"。结果「网页书」里
   有一个画像还未知的点（弹性盒）→ 整本书被留下 → 只选「样式与布局」时仍然挑出「网页书」的
   「网格布局」。**正确语义是"在选中主题里找"，必须逐点筛。**
2. **越界校验用了原始画像**：LLM 硬塞一个被排除主题的点会被判成"画像里有，合法"，
   过滤形同虚设。改成对着 `scoped` 校验后，测试立刻从"没拦住"变成"拦住了"。

## 测试数据的一个坑

裁剪后已掌握点可能低于 `MIN_POINTS=3`，于是先报"知识点太少"——那样测的就不是过滤本身了。
测试画像改成每个主题各留 3 个「学过」的点。

## 实测

| 项 | 结果 |
| --- | --- |
| 只选「网页基础」 | prompt 含网页基础点、**不含**盒模型/颜色与单位/字体与排版；出题用到的点合法 |
| LLM 硬塞「盒模型」 | **拦下**：「出题越界：声明的知识点不在画像里…盒模型」 |
| 新点选书 | 只选样式 → 颜色与单位；只选网页 → 网格布局 |
| 看板 | 2 个复选框、默认全选、含 localStorage、**复选框在 next 表单内部** |
| 全不选 | **400**「至少要选一个主题：当前一个都没选，无法出题」 |
