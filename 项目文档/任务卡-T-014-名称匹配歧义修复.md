# 【T-014】 修 Bug：改状态的名称匹配歧义

## 任务边界

- 所属模块：[[模块-命令行入口]]（看板动作）、[[模块-知识画像]]（画像写入）
- 对应需求/验收：T-014；A-07 的健壮性补充
- 目标行为：改状态时**精确匹配优先**；多个候选（归一化后同名）时报错并列出候选（带主题）让客户端重试；**禁止模糊命中后报成功**。
- 本任务不做：不改看板交互方式、不改动作白名单、不做名称自动去重/合并。
- 前置依赖：T-013（已验收）。

## 复现与根因（C 段流程：先给可确认事实）

**现场数据**（客户真实画像 profile/knowledge.md，26 个知识点）：

| 条目全名 | 主题 | 归一化后 |
| --- | --- | --- |
| 列表（ul/ol/li） | HTML 基础 | 列表 |
| 列表 | Python 基础 | 列表 |

**根因**：归一化（去掉结尾「（主题）」）会让两条不同主题的条目撞成同一个名字；\`set_level\` / \`mark_done\` 用「第一个归一化命中」定位，于是 POST 改「列表」时命中了 **HTML 基础** 那条，页面还报成功，目标条目没变。

注意：这不是「前缀匹配」问题（没有做 startswith），而是**归一化后重名**。

## TDD 记录

### 1. 失败测试

- 测试文件/名称：tests/test_t014_name_match_bug.py（12 项；全项目 283 项）
- 它要描述的行为：精确同名优先、完整名称（带主题）可用、归一化多条 → 歧义报错并给候选、歧义禁止报成功、mark_done 同样处理、看板层歧义变成可展示失败且不写文件
- 首次失败原因：9 项失败 —— 精确匹配被模糊匹配抢走、歧义不报错、mark_done 同样缺陷

### 2. 最小实现

- 拟修改文件：src/profile.py（新增 _resolve_point_index / _candidate_label；set_level 与 mark_done 改用它）
- 最小改动说明：
  - 统一一个解析器，匹配顺序：① 精确同名 ② 归一化名且唯一 ③ 多条 → 报歧义（列出候选与主题） ④ 零条 → 报错（列出全部候选）
  - set_level 与 mark_done 都改走该解析器，避免只修一半
- 不新增的复杂度：不做自动合并重名、不做模糊/拼音/子串匹配、不改文件格式
