# 模块-笔记同步

## 1. 职责与边界

### 模块职责

按文档 ID 从飞书开放平台只读拉取文档正文（含其全部子文档，递归），转换为 markdown 存入本地 `notes/` 目录。

### 不负责什么

- 不写回飞书（本期无任何写操作）。
- 不理解、不提炼笔记内容（那是 [[模块-知识画像]] 的事）。
- 不做增量/差异同步策略（本期重复拉取即覆盖，但失败时不得覆盖已有文件）。

### 上下游关系

| 方向 | 模块/系统 | 交换内容 | 约定 |
| --- | --- | --- | --- |
| 输入 | 命令行入口 | 文档 ID | 字符串；来自命令行参数 |
| 输入 | 飞书开放平台 | tenant_access_token、文档块内容 | 凭证从 `.env` 读取，缺失即报错退出 |
| 输出 | 本地 `notes/` | markdown 文件 | 文件名含文档 ID；写成功才覆盖旧文件 |

## 3. 核心流程

### 流程： 拉取一篇文档

1. 命令行入口传入文档 ID。
2. 检查 `.env` 中 App ID / Secret 存在；用其换取 tenant_access_token。
3. 调用 docx API 分页取回文档全部块，按块类型（标题/段落/代码块/列表）转 markdown。
4. 先写 `notes/<id>.md.tmp`，成功后替换为 `notes/<id>.md`。

## 5. 状态、错误与排查

| 状态/错误码 | 触发条件 | 用户可见结果 | 系统行为 | 优先排查位置 | 是否可重试 |
| --- | --- | --- | --- | --- | --- |
| 凭证缺失 | `.env` 无 App ID/Secret | 报错提示检查 `.env` | 退出，不动文件 | `.env` | 修复后重试 |
| 无权限/文档不存在 | 飞书返回权限类错误码 | 报错并显示文档 ID | 退出，不覆盖旧文件 | 飞书应用权限配置 | 是 |
| 网络/接口失败 | 超时、5xx | 报错 | 保留旧文件 | 网络与飞书服务状态 | 是 |

### 应用权限前置条件（实测确认，2026-09-26）

飞书自建应用必须先开通「应用身份权限」，否则接口返回 `99991672 Access denied`。已实测确认：

| 步骤 | 需要的权限 | 未开通时的表现 |
| --- | --- | --- |
| 换 tenant_access_token | 无（凭证有效即可） | 凭证错误码 |
| `wiki/v2/spaces/get_node` | `wiki:node:read`（或 `wiki:wiki:readonly` / `wiki:wiki`） | `99991672`，列出上述 scope |
| `docx/v1/documents/{id}/raw_content` | `docx:document:readonly`（或 `docx:document`） | `99991672`，列出 docx scope |

注意区分两类失败：**「应用没开权限」**（本表，需在开放平台后台开通）与**「文档没授权给应用」**（需把文档分享给应用）。两者错误码不同，排查时先看报错里给出的 scope 清单。

### 子文档递归与命名（T-009 实测）

| 项 | 约定 |
| --- | --- |
| 落盘命名 | 每篇一个文件，文件名为该节点在飞书里的 **wiki 节点 token**（父、子统一），如 `NMq0wmqEDiRkiAk2d8acp7mHnVd.md` |
| 递归来源 | 优先 `GET /wiki/v2/spaces/{space_id}/nodes?parent_node_token=…`（分页聚合） |
| 兜底来源 | 缺 `wiki:node:retrieve` 时，读父文档块里的**文档提及**（`mention_doc.token`）作为子节点，再用 `get_node`（需 `wiki:node:read`）解析 |
| 叶子优化 | 只对 `has_child=True` 的节点调列举接口，叶子节点不白跑请求 |
| 失败处理 | 父文档失败 → 抛错不写文件；子文档失败/无权 → 跳过并记录 (节点 ID, 原因)，其余继续 |
| 深度 | 默认 `max_depth=5`，防止异常结构无限递归 |

**实测规模**：客户学习库 = 父文档 265 字符 + 10 篇子文档，合计 34,300 字符（单篇最大 13,236 字符 / 719 行）。
**父文档不是正文所在**——它是主题清单，正文在子文档里；同步必须带递归才有意义。

### 真实文档形状（实测确认，2026-09-26，T-002）

跑真实文档才暴露的约定，转 markdown 时必须遵守：

| 事实 | 影响 | 处理 |
| --- | --- | --- |
| 整篇文档的块都挂在 `page` 块下（parent_id 指向 page） | page 当一层算会让整篇笔记统一多两个空格 | page 视为容器，子块深度不递增 |
| 文档提及 `mention_doc` 旁边同时带一个**空的 `text_run`** | 只判 `text_run` 会把提及吞成空串（静默丢内容） | 先判非文本元素，再判 `text_run` |
| 飞书把提及的 `title` 计入 `raw_content` | 提及标题是笔记内容的一部分 | 渲染为 `[文档提及: 标题]` |
| `raw_content` 每块一行，提及只出标题 | 可用于内容一致性对账 | 把「块文本 + 提及标题」按块序拼起来应与 raw_content 逐行一致 |

块类型与 `raw_content` 的行对应关系：1=page、2=text、3..11=heading1..9、12=bullet、13=ordered、14=code、15=quote_container。
代码块 `language` 枚举：1=plaintext、22=go、48=python（其余见 `src/sync.py` 的 `CODE_LANGUAGES`）。

### 已支持的块类型（T-002 + T-009 实测补齐）

| block_type | 含义 | 渲染 |
| --- | --- | --- |
| 1 / 2 | 页面 / 段落 | 纯文本（page 是容器，不给子块加缩进） |
| 3..11 | 标题 1..9 | `##` ~ `##########` |
| 12 / 13 | 无序 / 有序列表 | `- ` / `N. ` |
| 14 | 代码块 | 围栏 + `CODE_LANGUAGES` 语言标记 |
| 15 | 引用容器 | 正文 |
| 24 / 25 | 分栏 / 分栏列 | 容器，保留子块正文、不产生标记 |
| 27 | 图片 | `[图片]`（不下载本体、不把 token 当正文） |
| 30 / 43 | 内嵌表格 / 内嵌看板 | `[内嵌表格]` / `[内嵌看板]` |
| 31 / 32 | 表格 / 单元格 | **markdown 表格**（按 `table.property` 行列还原，单元格内容照实取出） |

> [!warning] 未知情况
> 未识别的块类型降级为占位文本 `[未支持的块: <block_type 数字>]`，不得静默丢弃、也不得猜测其内容。
> 补齐依据：实测客户全库块类型分布 = {1,2,3,4,5,6,12,13,14,24,25,27,30,31,32,43}，补齐后占位块从 101 降到 0。
> 实测确认 T-001 测试 wiki 节点的 `obj_type` 为 `docx`，`raw_content` 适用；表格类节点的处理留待遇到时再定。
