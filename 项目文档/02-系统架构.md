# 学习领航员 系统架构

## 设计目标与约束

- 核心目标：读飞书笔记（含子文档）+ 书籍蒸馏稿 → 维护知识画像与知识地图 → 生成可验收的动手任务 → 回写画像（见 [[01-需求与范围确认]]）。
- 使用边界：单人自用，本地命令行工具；飞书侧只读。
- 关键约束：凭证、笔记原文、蒸馏稿原文不进仓库；不依赖数据库；客户主力语言 Python（正学 C++，前端仅 HTML/CSS 基础），实现与出题默认 Python。
- 关联需求：[[01-需求与范围确认]]

## 两类输入的分工（核心设计）

- **飞书笔记 → 知识画像**：笔记是「我接触过什么」的证据，提炼后进入 `profile/knowledge.md`（学过/做过/存疑）。
- **书籍蒸馏稿 → 知识地图**：蒸馏稿是「这本书还有什么该学」的路线图，导入后进入 `profile/syllabus.md`（书名 → 章节 → 知识点）。
- 出题时两者汇合：任务主体用画像里已掌握的点，新知识点从地图里按书序取「画像中还没有的下一个」。

## 模块边界

| 模块 | 负责什么 | 不负责什么 | 对外输入/输出 | 依赖 | 模块笔记 |
| --- | --- | --- | --- | --- | --- |
| 笔记同步 | 按文档 ID 拉取飞书文档及其子文档正文，存为本地 markdown | 不写回飞书；不做内容理解 | 文档 ID → notes/*.md | 飞书开放平台 | [[模块-笔记同步]] |
| 书籍蒸馏导入 | 读取 books/ 蒸馏稿，生成/更新知识地图 syllabus.md | 不做 OCR、不做蒸馏本身（客户用 DeepSeek 自行完成） | books/*.md → profile/syllabus.md | LLM API | [[模块-书籍蒸馏导入]] |
| 知识画像 | 从笔记 markdown 提炼知识点，维护学过/做过/存疑状态 | 不生成练习任务；不维护知识地图 | notes/*.md → profile/knowledge.md | LLM API | [[模块-知识画像]] |
| 任务生成 | 基于画像 + 地图输出一个动手任务（目标+验收方式） | 不替客户写代码 | 画像+地图 → 任务描述文本 | LLM API | [[模块-任务生成]] |
| 命令行入口 | 提供 sync / import / distill / next / done / serve 六个命令，读写配置 | 不含业务逻辑本身；看板页面只读，不接收任何写请求 | 命令行参数 → 各模块调用 | 以上模块 | [[模块-命令行入口]] |

## 主数据流

### 流程： 一次学练循环

1. 客户执行 `sync <文档ID>`，笔记同步模块用 `.env` 凭证换取 tenant_access_token，递归拉取该文档及子文档正文存入 `notes/`。
2. 执行 `distill`，知识画像模块读取新增/变更的笔记，调用 LLM 提炼知识点，合并进 `profile/knowledge.md`（失败时保留旧文件）。
3. 执行 `next`，任务生成模块读取画像与地图，调用 LLM 生成任务：主体只用「学过/做过」的知识，至多一个新知识点（优先取地图中按书序的下一个未掌握点），附验收方式。
4. 客户线下写代码完成任务；执行 `done <知识点> <产出路径>`，画像状态更新为「做过」并记录证据。

### 流程： 接入一本书

1. 客户自行用 DeepSeek 蒸馏电子书，把产出的 markdown（顶部带书名 frontmatter）放入 `books/`。
2. 执行 `import <文件名>`，书籍蒸馏导入模块调用 LLM 把蒸馏稿结构化为 章节 → 知识点 清单，合并进 `profile/syllabus.md`。
3. 之后 `next` 出题即可引用该书的地图。

## 技术选型

| 层级 | 选择 | 选择原因 | 已知限制 |
| --- | --- | --- | --- |
| 客户端/前端 | 无，命令行 | 自用工具，CLI 最简 | 无图形界面 |
| 服务端/任务处理 | Python 3.11+，标准库 + requests | 客户主力学习语言，练手一致 | 需联网调用两个外部 API |
| LLM 调用 | Kimi Coding Plan（api.kimi.com/coding/v1，模型 kimi-k2.7-code，KIMI_API_KEY）为主；Kimi 开放平台按量（api.moonshot.cn/v1，MOONSHOT_API_KEY）次之；DeepSeek（api.deepseek.com/v1，deepseek-chat）备用；OpenAI 兼容 chat/completions，标准库 urllib 直连 | 客户已购 Coding Plan；不引入 SDK 依赖 | coding plan 与按量 Key/端点不通用；moonshot-v1 系列已下线；首选 provider 缺 Key 时自动降级 |
| 数据存储 | 本地文件（markdown + 简单 frontmatter） | 单人自用，可读可 git 管理 | 无并发支持 |
| 测试与交付 | pytest | Python 主流，dsh 可直接执行 | 外部 API 相关测试需打桩 |

## 接口与数据所有权

| 数据/接口 | 所有者 | 写入者 | 读取者 | 校验边界 | 敏感级别 |
| --- | --- | --- | --- | --- | --- |
| `.env`（App Secret、LLM Key） | 客户 | 客户手工 | 命令行入口 | 启动时检查存在性，缺失即报错退出 | 敏感，不进仓库 |
| `notes/*.md` 笔记副本 | 笔记同步 | 笔记同步 | 知识画像 | 拉取失败不覆盖已有文件 | 内部，不进仓库 |
| `books/*.md` 蒸馏稿 | 客户 | 客户手工放入 | 书籍蒸馏导入 | 导入前校验 frontmatter 与基本格式 | 内部，不进仓库 |
| `profile/knowledge.md` 画像 | 知识画像 | 知识画像/命令行(done) | 任务生成 | 写入先落临时文件再替换 | 内部 |
| `profile/syllabus.md` 地图 | 书籍蒸馏导入 | 书籍蒸馏导入 | 任务生成 | 写入先落临时文件再替换 | 内部 |
| LLM 请求内容 | 客户 | 画像/导入/任务生成 | LLM API | 发送前不含凭证；客户已知情同意 | 敏感（含笔记/蒸馏内容） |

## 变更规则

- 新功能先回到 [[01-需求与范围确认]]，确认是否在范围内。
- 涉及模块边界、数据流或技术选型时，先更新本文档，再创建实现任务。
- 某个模块内部的具体行为放入对应模块笔记；一次性测试输出放在任务卡，不写入本文档。
