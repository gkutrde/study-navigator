# 【T-009】 sync 子文档递归

## 任务边界

- 所属模块：[[模块-笔记同步]]
- 对应需求/验收：[[01-需求与范围确认]] F-01；A-01 完整版（父 + 全部子文档）
- 目标行为：给定 wiki 文档 ID，递归拉取其全部子文档，各自落盘 notes/<节点 token>.md；无权的子文档跳过并报出 ID，已成功的部分保留。
- 本任务不做：不做增量同步、不写回飞书、不下载图片/附件本体、不合并成单文件。
- 前置依赖：T-002（已验收）。

## 验收示例

### 正常路径

- 给定：有子文档的 wiki 文档
- 当：python -m src.cli sync <wiki链接>
- 则：父文档 + 全部子文档各自落盘，stderr 列出每篇路径

### 异常或边界路径

- 给定：某个子文档无权访问
- 当：执行 sync
- 则：跳过该子文档、报出它的 ID、其余继续，退出码 0
- 给定：父文档失败
- 当：执行 sync
- 则：报错退出，不产生半成品

### 权限现状与兜底路径（重要）

- 列举子节点的接口 GET /wiki/v2/spaces/{space}/nodes 需要应用身份权限 **wiki:node:retrieve**；
  当前应用只有 wiki:node:read，实测直接报 99991672。
- 兜底：父文档块里的**文档提及**（mention_doc）带着子文档 token，而 get_node 用的是已有的
  wiki:node:read，所以改用「读父文档提及 → 逐个 get_node 解析 → 继续递归」。
  实测该兜底完整覆盖了本库的 10 篇子文档。
- 权限开通后无需改代码：会优先走列举接口（更可靠，能拿到 has_child 与真实层级）。
- 提示语会明确写出「本次已退化 + 缺哪个权限」，不让用户以为走的是正常路径。

## 实测发现的四个问题（真实笔记才暴露）

1. **缺 wiki:node:retrieve**：列举子节点被拒 → 增加文档提及兜底（见上）。
2. **对叶子节点也调列举接口**：白跑请求且会误导报错 → 改为只在 has_child=True 时调。
3. **兜底发现的子节点解析失败会静默继续**：拿 wiki token 当文档 ID 去取块，会报出「块响应异常」这种误导信息 → 改为解析失败即跳过并如实记录原因。
4. **真实块类型大面积未支持**：表格（31/32，实测 68 个单元格）、图片（27）、内嵌表格（30）、内嵌看板（43）、分栏（24/25）此前全被降级成占位块，全库 101 处。已补齐渲染：
   - 表格 → markdown 表格（按 table.property 的行列还原，单元格内容照实取出）
   - 分栏 → 容器，保留子块正文（不产生标记）
   - 图片 / 内嵌表格 / 内嵌看板 → 位置标记，不下载、不把内部 token 当正文写入
