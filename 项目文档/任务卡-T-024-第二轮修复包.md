## 修复记录

### M-01（P1 真 bug）看板「回写」按钮无参数入口

**复现**：按钮是个裸 `<button>`，而 `done` 要求 `name` + `path` → 点了必失败（实测表单字段为**空**）。

**修法**：回写表单补三个字段：
- `name`：**下拉**，候选取自 `tasks.md` 最近一次任务涉及的知识点（含新点，新增 `read_latest_task_points`）；还没出过题时退化为文本输入；
- `path`：产出路径（必填）；
- `recite`：可选费曼复述。
入参白名单相应扩为 `{name, path, recite}`，看板与 CLI 走同一条 `mark_done`。

### M-02（P1 真 bug）统计区缺「输出」态

**复现**：统计区硬编码三态 → 四态画像下「输出」计数**根本不显示**（实测画像里有 1 个「输出」点，统计区里没有）。

**修法**：改成遍历 `LEVELS`，以后再加状态也不会漏。

### M-03 explain 无缓存

**修法**：讲解落盘 `profile/explanations/<安全名>.md`（frontmatter 记出处 + 正文），
同名命中缓存**零 LLM 调用**；加 `--refresh` 强制重生成。
知识点名里的 `/ : * ?` 会被过滤，过长用哈希兜底——**不拼危险路径**。

### M-04 LLM 无重试

**修法**：新增 `TransientLLMError` 把「可重试」与「不可重试」分开：

| 情况 | 行为 |
| --- | --- |
| 429 限流 / 5xx / 超时 / 连接失败 | **指数退避重试 ≤2 次**（1s → 2s） |
| 429 但是额度/余额类（insufficient / quota / balance…） | **不重试**，直接中文提示「额度或配额不足…或换 provider」 |
| 400 参数错 / Key 无效 | 不重试 |

### M-05 serve 端口占用抛 traceback

**修法**：绑定失败 catch OSError → 中文提示「启动失败：端口 N 无法监听（原因）。换一个端口重试：--port N+1」，退 1，无 traceback。

> [!warning] M-05 实测挖出更深一层问题
> 写测试时发现：**真占住端口，`serve` 仍能绑定成功**——因为 `ThreadingHTTPServer.allow_reuse_address = True`
> 在 Windows 上会**抢占**别人已监听的端口（两个服务同时跑同一个端口）。
> 这比"抛 traceback"隐蔽得多，已把 `allow_reuse_address` 改为 `False`。
> 代价是重启偶尔遇到 TIME_WAIT，可接受。
> 我的测试也从"真占端口"改为打桩（真占端口测不出失败路径）——**测试手段被实测纠正**。
