# 【T-034】 chat 交互模式

## 客户要什么

> 像在正常 agent 里一样连续对话，点完直接能聊。

T-033 交付的是「点按钮弹终端跑**单次** chat」，不满足连续对话。本任务主方案是**看板内嵌聊天面板**。

## 修法

### 主方案：看板聊天面板

| 层 | 做法 |
| --- | --- |
| 会话层 | 新模块 `src/chat_session.py`：历史按任务隔离、留档 `profile/handoff/<任务>.chat.md`、prompt 组装与裁剪 |
| 面板 UI | 每张任务卡片下方 `.chat-panel`：折叠按钮 → 展开后是 `chat-log` + 输入框 + 发送 |
| 自动首问 | 首次展开且无历史时，**自动发出**首条引导提问（我的代码哪里不足？…） |
| 每轮 | 服务端把「handoff 全文 + 该任务历史 + 新消息」拼 prompt → `subprocess` 列表参数（`shell=False`）调 `dsh --profile headless` |
| 渲染 | `fetch` 异步把回答追加进面板——**不整页刷新、不跳滚动** |
| 裁剪 | 历史超 30000 字符：**handoff 全文保留**，只裁最旧轮次并注明「已裁剪 N 轮」 |

### 备选：终端 REPL

新模块 `src/repl.py`：`chat <时间戳>` **不带问题**进交互循环（提示符「你：」，`exit/quit` 退出）；
带问题保持 T-032 单次模式。循环逻辑做成可注入（ask / read_line / write），所以不依赖真实终端也能测。

### T-033 弹窗降级

弹窗保留但**不再是主路径**，输出里明确写「次级入口」，并提示「不想用终端就忽略它，直接用面板」。

### 验收时看到的副作用（已如实记录）

DSH 的回答里出现了这句：「工作区 `C:\\Users\\25088\\Documents\\kimi\\study\\card.html` 里躺着的是一份 **17 行、结构完整的** 名片页」。
这印证了 T-032 那个**安全缺陷是真的**：`dsh --profile headless` 子进程有工具权限、工作区就是本仓库，
它会**主动去读项目目录里的文件**（甚至可能是编的）。面板让这个调用更容易触发，所以该缺陷值得尽快收口。

## A 方案收口：展开面板**不自动跑子进程**（2026-09-29 客户选定）

**为什么**：真机验收时看到 DSH 回答里引用了本仓库的文件（`card.html 里躺着一份 17 行、结构完整的名片页`）——
印证了 T-032 引入的安全缺陷：`dsh --profile headless` 是有工具权限的子进程、工作区就是本仓库，
**会读（也可能写）项目目录**。面板让调用更容易触发，所以收口。

| 改动 | 内容 |
| --- | --- |
| 去掉自动首问 | 展开面板只显示输入框；第一次调用必须由用户按「发送」 |
| 面板明示风险 | 提示区直接写「点发送会在本机启动一个 dsh 进程，它**能读写本项目目录**」 |
| 保留 | CLI 的 `chat` 单次/REPL 模式不变（那是用户显式敲的命令，不算点一下就自动跑） |
