## 已知限制与后续建议

- T-001 已通过（应用已开通 `docx:document:readonly` 等应用身份权限）。
- 裸 token 被当作 docx 文档 ID 处理；wiki 节点必须用 `/wiki/` 链接（后续可补自动回退）。
- T-002 只做单文档，因此 A-01 目前只到「单文档部分通过」；子文档递归是 T-009。
- 已支持常见块：表格（31/32）渲染为 markdown 表格、分栏（24/25）保留内容；图片（27）与内嵌表格/看板（30/43）只留位置标记**不下载本体**；其余未识别块仍降级为 `[未支持的块: N]`。
- 多层列表缩进按父子关系固定两空格一级，未做精细美化。
- T-003 的 Kimi 侧未做真实连通验证：`MOONSHOT_API_KEY` 为空；代码与自动降级路径已就绪。
- Kimi 模型名不得回退到 `moonshot-v1` 系列（2026-08-31 已下线），已有回归测试锁定。
- 画像只增不删：提炼、`done`、看板改状态都可能新增条目（T-023 起 `done` 也会为新点新增）；没有删除/合并界面，需要手工编辑 `profile/knowledge.md`。
- Kimi Code CLI 登录态有效期短（实测约 10 分钟级），过期需重新 `/login`；工具不自动刷新（T-011 明确不做）。
- `distill --all` 单篇失败**不回滚**：成功篇目照常写入，失败篇目明确报出（退出码 1）。实测 12 篇里 1 篇因 LLM 返回 JSON 语法错误失败，重跑即可重试该篇（幂等）。
- 出题门槛是「已掌握（学过/做过）≥3」。T-016 全量提炼后画像达 105 点、已掌握 69 个，实测 `next` 已能正常出题。
- 题库标签必须与画像知识点名称**逐字一致**，否则永远命中不了；客户改画像名称后需同步改 `profile/assignments.md`（有测试会报出不一致）。
- 命名对齐（T-021）只信 **high 置信度**（350/3168）；medium 档 1509 条里混有不少硬凑，未纳入 —— 若人工抽查后可再提高"下一个点"的精度。
- 「输出」态目前只记录复述文字，**不评判复述质量** —— 判"讲得好不好"仍由人来做。
- `import` 目前是最小实现（读 frontmatter 书名 + LLM 出章节知识点 + 写 syllabus.md）；格式校验与逐项缺项报错仍属 T-010。
- 看板已支持固定动作交互（T-013）：按钮触发 sync/distill/next/done + 手工改状态；**仍然没有自由命令入口**（动作名与入参双白名单），样式仍从简留白。
- 看板的「提炼知识点」按钮已改为**全量提炼**（T-016），并逐篇汇报成败。
- 看板里的 sync/distill 以「最近一篇笔记」为输入（页面无处输入文档 ID）；要指定文档仍需命令行。
- M2（书籍路线）未开始：`books/` 目录不存在，需客户先放入 DeepSeek 蒸馏稿。
