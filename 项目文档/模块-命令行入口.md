# 模块-命令行入口

## 1. 职责与边界

### 模块职责

提供六个命令 `sync / import / distill / next / done / serve`，负责解析参数、加载 `.env`、调用对应模块并打印结果。
（`serve` 是 T-012 新增的本地只读看板，不属于业务闭环，只读展示 profile/ 下的产物。）

### 不负责什么

- 不含任何业务逻辑（同步、提炼、出题的实现都在各自模块）。
- 不管理凭证内容本身（只负责加载与缺失检查）。

### 上下游关系

| 方向 | 模块/系统 | 交换内容 | 约定 |
| --- | --- | --- | --- |
| 输入 | 客户 | 命令行参数 | `sync <文档ID>`、`import <文件名>`、`distill`、`next`、`done <知识点> <产出路径>` |
| 输入 | `.env` | 飞书凭证、LLM Key | 缺失时明确报错退出 |
| 输出 | [[模块-笔记同步]] / [[模块-知识画像]] / [[模块-任务生成]] | 函数调用 | 单进程内直接调用 |

## 3. 核心流程

### 流程： 执行任意命令

1. 解析子命令与参数，参数非法时打印用法。
2. 加载 `.env`，检查该命令需要的键存在，缺失即报错退出（指出缺哪个键）。
3. 调用对应模块函数，透传其输出与退出码。

## 4. 数据与接口

| 名称 | 调用方 | 输入 | 成功输出 | 失败输出 | 说明 |
| --- | --- | --- | --- | --- | --- |
| sync | 客户 | 文档 ID | 提示文件路径（含子文档清单） | 非零退出码+原因 | 调 [[模块-笔记同步]] |
| import | 客户 | books/ 中文件名 | 提示地图更新摘要 | 非零退出码+原因 | 调 [[模块-书籍蒸馏导入]] |

| next | 客户 | 无 | 任务描述文本 | 非零退出码+原因 | 调 [[模块-任务生成]] |
| done | 客户 | 知识点+产出路径 | 提示状态已更新 | 非零退出码+原因 | 调 [[模块-知识画像]] |

## 5. 状态、错误与排查

| 状态/错误码 | 触发条件 | 用户可见结果 | 系统行为 | 优先排查位置 | 是否可重试 |
| --- | --- | --- | --- | --- | --- |
| 参数错误 | 缺参数/未知命令 | 打印用法 | 退出码 2 | 命令拼写 | 修正后重试 |
| 凭证缺失 | `.env` 缺键 | 指出缺的键名 | 退出码 1 | `.env` | 修复后重试 |

## 7.1 命令表与退出码约定（八个命令）（T-007 实测）

| 命令 | 参数 | 退出码 0 | 退出码 1 | 退出码 2 |
| --- | --- | --- | --- | --- |
| `sync` | `<文档ID 或 wiki/docx 链接>` | 已落盘并打印正文 | 凭证缺失 / 飞书接口失败 | 参数个数不对 |
| `import` | `<books/ 中的文件名>` | 已更新 syllabus.md，**并提示接着跑 align** | LLM 配置或调用失败 | 文件不存在 / 参数不对 |
| `align` | `[--provider X]` | 已写 alignment.json 并打印对齐比例 | 画像/地图缺失、LLM 失败 | 位置参数 / provider 未知 |
| `explain` | `<知识点>` `[--refresh] [--provider X]` | 打印讲解 + 出处（书·章）；命中缓存标「来自缓存」 | 知识点不在地图、参考文本取不到、LLM 失败 | 参数个数不对 / provider 未知 |
| `review` | `<任务时间戳> <代码文件>` `[--provider X]` | 按该任务的**验收方式**点评代码，把「提交时间 + 评价 + 建议」留档到 tasks.md | 找不到任务块 / 读不到代码文件 / LLM 失败 | 参数个数不对 / provider 未知 |
| `chat` | `<任务时间戳>` [`问题`] | 带问题：单次答；不带问题：进交互模式（提示符「你：」，exit 退出）；两者都写留档（T-032/T-034） | 缺接力文件 / 没装 dsh / dsh 失败 | 参数个数不对 |
| `chat` | `<任务时间戳> <问题>` | 读 profile/handoff/<id>.md，拼成单段 prompt，调 `dsh --profile headless`（**subprocess 列表参数，不走 shell**）并透传输出（T-032） | 没有接力文件 / 没装 dsh / dsh 失败 | 参数个数不对 |
| `distill` | `<笔记文件>` 或 `--all`；`[--json] [--no-write] [--profile P] [--provider X] [--notes-dir D]` | 已更新画像并打印知识点 | LLM 失败 / 画像写入失败 | 文件不存在 / 参数不对 |
| `distill --all` | 全量提炼 notes/ 非空笔记 | 全部成功退 0 并逐篇汇报 | **有失败篇目退 1**（成功篇目仍写入） | `--all` 与文件参数同用 / provider 未知 |
| `next` | `[--profile P] [--provider X]` | 已出题并留档 tasks.md | 画像不足 / 出题失败 | 多余参数 / provider 未知 |
| `done` | `<知识点> <产出路径>` `[--recite <复述>] [--profile P]` | 状态已升「做过」/「输出」；**画像里没有的点会新增**（T-023 L-01） | 缺产出路径 / 画像缺失 | 参数个数不对 |
| `report` | `[--days N]` | 周报复盘：窗口内的状态迁移 / 任务完成 / 薄弱点 / 复习完成率（T-044） | 找不到画像 / --days 非整数 |
| `serve` | `[--port N] [--no-browser]` | 看板已启动并在前台阻塞 | 端口无法监听：中文提示 + 换端口建议，退 1，**无 traceback**（T-024 M-05） | 端口非数字 / 超出范围 |

## 7.2 看板（serve）的交互动作集（T-013 / A-07）

> [!note] 这不是 CLI 命令
> 下表是**网页上的固定动作**，只能在看板页面触发；命令行并不存在 `status` 这个命令。

看板从「只读」升级为「固定动作集交互」，边界**没有放宽**：

| 动作 | 入参 | 作用 |
| --- | --- | --- |
| `sync` | 无 | **「同步并提炼」**：同步成功后**接着跑增量提炼**（T-025），结果分 `【同步】`/`【提炼】` 两段；配了 `FEISHU_ROOT_DOC` 就同步整棵树，没配则同步最近一篇并说明怎么改成全树（T-023 L-05）。同步失败不再提炼；提炼失败不阻塞 |
| `distill` | 无 | **全量提炼 notes/ 下的非空笔记**（T-016），逐篇汇报成败 |
| `next` | 无 | 出题并留档 tasks.md，结果展示在页面上 |
| `done` | `name`, `path`, `recite` | 把某知识点标成「做过」并记录产出路径；`recite` 非空则升「输出」。**表单是完整的**：`name` 下拉取自最近一次任务涉及的知识点，`path` 必填，`recite` 可空（T-024 M-01） |
| `delete_task` | `when` | 按时间戳删掉一个任务块（**只动目标块**，tmp + replace）（T-027） | 找不到该时间戳 | 参数不对 / 多给键 |
| `review` | `task`, `code` | 按该任务的**验收方式**点评代码，留档「提交时间 + 评价 + 建议」（T-028） | 找不到任务块 / 代码为空 | 参数不对 / 多给键 |
| `handoff` | `task` | 生成 DSH 接力上下文（任务卡/代码/画像/出处/提问），一任务一文件（T-031） | 找不到任务块 | 参数不对 / 多给键 |
| `chat` | `task`, `message` | 面板里一轮对话：handoff + 该任务历史 + 新消息 → dsh headless，问答写留档（T-034） | 缺接力文件 / 缺消息 / dsh 失败 | 参数不对 / 多给键 |
| `explain` | `name` | 讲清一个知识点：地图定位 → 取参考文本 → LLM 讲解，并注明出处（T-022）；`name` 可以是**画像名**，会经对齐表映射（T-023 L-03） |
| `status` | `name`, `level`（+ 可选 `note`/`recite`/`path`） | 手工改状态；**表单只留 name+level**（T-026），选完即提交、原地更新；页面上多余的字段已归回写表单 |

**安全边界（硬性，长期有效）**：

1. **只有固定动作集**：动作名必须精确等于白名单，否则 400，且不调用任何操作。
2. **无自由命令入口**：页面没有任何命令输入框；服务端不接受「命令字符串」参数，只按动作名分派。
3. **入参白名单**：每个动作限定允许的键，多给一个键就整体拒绝（如 next 带 cmd 会被拒）。
4. **状态值不可注入**：手工改状态的 level 走 `profile.set_level` 的三态白名单。
5. 非法输入一律变成「可展示的失败结果」，不会把服务打崩；**失败时画像文件字节不变**。
6. 仍绑定 127.0.0.1、仍零新依赖、不做登录鉴权。

### serve 的视觉层（T-015）

- 视觉层单独放在 `src/dashboard.py` 的 `PANEL_STYLE` / `PANEL_JS`，与渲染逻辑分离，便于继续美化。
- 卡片网格（`minmax(21rem, 1fr)`）、知识点卡片、任务卡片、顶部固定动作区 + **四态统计**。
- **统计区遍历 `LEVELS`**，不是硬编码——T-024 M-02 的教训：硬编码会在新增状态时静默漏掉（当时四态画像里「输出」根本不显示）。
- **四态配色固定**（机检项）：`学过` 蓝、`做过` 绿、`输出` 紫、`存疑` 橙，各有一套前景/背景/边框；新增状态必须补色，否则测试会红。
- **不抢占端口**：`DashboardServer.allow_reuse_address = False`（T-024 M-05 实测：Windows 上设 True 会让新服务抢占已被监听的端口）。
- 响应式：`@media (max-width:640px)` 转单列；`prefers-color-scheme: dark` 跟随系统。
- **零外部依赖**：不外链 CDN/字体/图标，无 `<link>`、无 `<script src>`；只用内联 CSS + 原生 JS。
- 原生 JS 只做渐进增强（T-026 起：状态**原地提交**、统计原地更新、失败原地红字），**不新增任何入口**；无 `eval`、无 `location.reload`；`fetch` 只打固定动作路由。
- 原地更新靠三个钩子：卡片 `data-point`/`data-level`，统计 `data-stat="<状态>"`，错误槽 `.inline-error`。
- 状态两个控件分工：**chips**（点一下即改，`.chip.js-only`）/ **下拉 + 保存按钮**（无 JS 兜底与精确选择；有 JS 时按钮隐藏、选完即提交）。
- **不要留"绑定了但页面上没有该元素"的 JS**（T-026 实测：chips 被删后 PANEL_JS 里 4 处 `.chip` 成了死代码）。

> [!warning] 美化必须做的边界回归检查
> 每次改 UI 都要确认没有把 T-013 的边界改掉：页面无 cmd/command 输入框、表单 action 仍限定固定动作集、
> 画像内容仍被 HTML 转义、服务仍绑 127.0.0.1、未知动作仍 400。这些都有自动化测试兜底。

### serve 的只读约定（T-012，已由 T-013 扩展）

- **四个路由各自独立**（T-027）：`/` 首页（概览 + 最近一条任务）、`/knowledge` 知识画像、
  `/tasks` 任务中心、`/syllabus` 知识地图。页面之间只靠导航链接往来，**不做同页堆叠**——
  之前四路由返回完全相同的同一页（实测 12714 字符一模一样）。
- GET/HEAD 只读；**POST 仅接受 `/action/<固定动作名>`**（T-013）；PUT/DELETE/PATCH 仍然一律 405。
- **JSON 路径对所有动作通用**（T-027 修正）：`_handle_action_json(action, body)` 统一分派。
  之前只在 `status` 上生效，导致 JS 调 `explain` / `delete_task` 拿到一个空 303。
- POST 分两条路（T-026）：`Content-Type: application/json` → JSON 原地更新接口（当前用于 `status`，返回 `{ok, level, counts}`）；`application/x-www-form-urlencoded` → 表单路径，成功回 **303** 回首页（**无 JS 时的渐进增强兜底**）。
- **锚点定位与主按钮**（T-030）：每张任务卡片带 `id="task-<时间戳>"`，
  `出题 / 回写 / 提交作业` 成功后回 **303 + /tasks#`锚点**`，浏览器自动滚到那张卡片；
  同一分钟出两题时锚点会加 `-<order>` 后缀保证唯一。提交作业用 `.btn-primary`（主按钮样式）。
- **点「在 DSH 中继续」会弹终端**（T-033）：`cmd /c start 空标题 cmd /k <chat 命令>`，
- **卡片下方有聊天面板**（T-034，主入口）：点展开后首条引导提问自动发出，之后在面板里连续追问；历史按任务隔离并留档到同名 `.chat.md`。
  窗口保持打开；列表参数 + `shell=False`，引号自己处理；
  非 Windows / 弹窗失败**静默降级**到页面上的文字指引。
- **渐进增强契约（长期）**：任何新交互都必须在"没有 JS"时仍能完成（提交按钮始终存在于 DOM）；JS 只做体验优化。
- JS 增强元素统一标 `js-only`，样式默认 `.js-only{display:none}`，由脚本加 `html.js` 打开——
  这样"没 JS 时该藏的东西一定藏得住"，不用在每个元素上判断。
- 除固定动作外的 POST 路径（如 `/action/exec`）返回 400，不执行任何东西。
- 每次请求现读 `profile/` 下文件；服务期间与停服后都不改动任何文件（有测试用哈希快照锁定）。
- 页面：`/` 首页（文件清单 + 更新时间）、`/knowledge`、`/tasks`、`/syllabus`；文件缺失时页面提示「还没有 …：先运行相应命令生成」。
- 样式刻意从简并留白（配色/卡片/暗色模式/字号层级），供客户日后自己美化练手。

约定：
- 用法串与分派共用 `KNOWN_COMMANDS`，避免「文档写了但代码没有」。
- **参数校验先于凭证/LLM 加载**：参数错就退 2，不能因为没配 Key 给出误导性报错。
- 「画像不足」（知识点不够）算正常路径，退 0 并给中文提示，不算错误。
- **缺前置产物统一退 1**（T-017 I-3）：`next`/`done` 找不到画像都是退 1，并提示「先运行 sync 同步笔记，再运行 distill --all 生成画像」；
  `import` 找不到蒸馏稿仍退 2 —— 那是**用户传参错误**，与 `sync`/`distill` 处理不存在的文件一致。
- 文档一致性有测试兜底（`tests/test_t017_docs_consistency.py`、`tests/test_t018_readme.py`）：
  命令表必须等于 `KNOWN_COMMANDS`、README 里的 `--flag` 必须真实存在、目录树必须与 `src/` 一致。
