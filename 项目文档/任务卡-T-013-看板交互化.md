# 【T-013】 看板交互化

## 任务边界

- 所属模块：[[模块-命令行入口]]
- 对应需求/验收：[[01-需求与范围确认]] F-06；A-07
- 目标行为：看板页面上固定按钮触发 sync / distill / next / done 并展示结果；知识点状态可手工改成 学过/做过/存疑 并落盘 knowledge.md。
- **安全边界（硬性，不可放宽）**：只有固定动作集，**不存在任何「自由命令入口」**；动作名与动作入参都走白名单；仍标准库 http.server + 绑定 localhost + 零新依赖；不做登录鉴权；网页不代写任务代码。
- 前置依赖：T-012（已验收）。

## 验收示例

### 正常路径

- 给定：serve 已启动
- 当：点「出题」按钮
- 则：执行 next 并把新任务展示在页面上，留档 tasks.md
- 当：把某知识点改成「学过」并保存
- 则：knowledge.md 里该知识点状态变更，其他知识点不动

### 异常或边界路径

- 给定：请求一个不存在的动作
- 当：POST /action/drop_database
- 则：400，报「未知动作 / 固定动作集」，**不执行任何操作**
- 给定：状态值非法（如「精通」）或知识点不存在
- 当：提交状态表单
- 则：400，画像文件字节不变
- 给定：动作收到多余参数（如 next 带 cmd）
- 当：提交
- 则：400 拒绝，不执行

## 安全边界的落实方式（重点）

| 边界要求 | 实现 |
| --- | --- |
| 只有固定动作集 | 动作名必须精确等于白名单；否则 400，且不调用任何操作 |
| 无自由命令入口 | 页面**没有**任何命令输入框（测试断言无 name=cmd / name=command、无 textarea）；服务端不接受「命令字符串」这种参数，只按动作名分派 |
| 入参也受限 | 每个动作有允许的键集合，多给一个键就整体拒绝 |
| 状态值不可注入 | level 走 profile.set_level 的三态白名单 |
| 不暴露外网 | 仍绑定 127.0.0.1 |
| 零新依赖 | 只用标准库（http.server / urllib.parse / html） |

## 实测结论（A-07，真实 HTTP）

在客户画像的**副本**上跑（真实画像全程哈希未变）：

| 验收点 | 结果 |
| --- | --- |
| 页面按钮触发命令 | 点「出题」→ HTTP 303，生成任务「做一个纯 HTML 的『我的 CS 学习主页』单页」，并在 tasks.md 留档 |
| 手工改状态落盘 | 把 3 个知识点改为「学过」→ 副本 knowledge.md 对应状态变更；已掌握数变为 11 |
| 无自由命令入口 | 首页四个固定按钮；无 cmd / command / textarea；drop_database / exec / shell / sync2 全部 400 |
| 非法输入不写文件 | 非法状态值 / 未知知识点 / 多余参数 → 全部 400，画像字节不变 |
| 真实画像 | sha256 哈希未变（副本与原件分离） |

补充观察：带空格的动作名（如 rm -rf /）在 HTTP 客户端层面就被拒（URL 不允许控制字符 / 空格），**根本到不了服务端**；服务端本身也只认白名单。
