# 【T-030】 任务中心排序与提交入口可见性

## 客户反馈

> 出题后新任务在列表最下面、找不到提交按钮。

## 取证（动手前）

| 项 | 实测 |
| --- | --- |
| ① 倒序 | **已经是对的**（T-027 写的 `reversed(records)`）——但**同一时间戳**时会把文件内先后也翻过来 |
| ② 锚点定位 | **完全没有**：卡片无 id、无 `scrollIntoView`、成功后固定跳 `/` |
| ③ 提交按钮 | 就是 `class="chip"`（29 号灰蓝小圆角），三张卡都是，**不醒目** |

所以真正要修的是 ②③，外加 ① 的同时间戳边角。

## 修法

| 项 | 做法 |
| --- | --- |
| ① 倒序 | `sorted(records, key=(when, order), reverse=True)`——用**稳定排序**替掉 `reversed()`；`TaskRecord` 加 `order`（文件内次序），同分钟时后写入的仍在上 |
| ② 锚点 | 每张卡片带 `id="task-<时间戳>"`；出题/回写/提交后 `handle_action` 返回 **303 + `/tasks#task-...`**，浏览器自动滚过去；卡片再闪一下（`task-flash`）让人看清是哪张 |
| ③ 主按钮 | 新增 `.btn-primary`（主题色底 + 白字 + 更大内边距），提交作业改用它；表单改纵向排列，标题在 chips 下方 |

### 锚点唯一性（同一分钟出两题）

锚点直接取时间戳会撞：两题都在 `15:05` 时卡片 id 相同——**HTML 非法、锚点只跳到第一张**。
实现 `task_anchors(records)`：只有时间戳重复时才加 `-<order>` 后缀，
普通情况仍是干净的 `task-<时间戳>`。

## 实测抓到的两个真 bug（都不是客户报的那三条）

### 1. HTTP 层吞掉了跳转锚点 → 出题后页面**直接空掉**

给 `handle_action` 加好锚点后，Playwright 点出题，结果浏览器停在 `/action/next`，**一张卡片都没有**。

根因：`do_POST` 里写死 `Location: "/"`，把我返回的 `/tasks#task-...` 丢掉了；
浏览器于是跟着当前 URL 又发一次 GET → 404 空页。

之前所有测试都直接调 `handle_action`，**没有一条走真实 HTTP 层**，所以全都绿的。
修法：新增 `handle_post_request`（返回 4 元组带响应头），`do_POST` 用它把 Location 透传；
并补两条**真发 HTTP** 的回归测试。

### 2. 同一分钟出两题 → 锚点 id 相同

Playwright 报 strict mode violation 才暴露。见上「锚点唯一性」。

> 这两个都说明：**只看"数据层对不对"不够**，得让真实浏览器走一遍。
