# 【T-026】 状态切换即时化

## 任务边界

客户要求：改状态**不要保存按钮、不要跳回顶部**。

- 模块：[[模块-命令行入口]] ｜ 前置：T-024 ｜ 验收：点 chip 后 300ms 内该条目变色且统计更新、滚动位置不变；失败时提示且不跳变；既有测试全绿
- **硬约束（客户点明）**：渐进增强（**无 JS 可提交**）+ 失败**原地**提示

## 修法

### 1. 表单瘦身

状态表单只留 `name` + `level``（下拉）+ 兜底提交按钮；
**产出路径 / 复述 / 说明三个输入框全部移出**，归 T-024 M-01 的回写表单管。
（T-026 前它们是挤在状态表单里的，既冗余又会让人以为"改状态还要填路径"。）

### 2. 原地更新（渐进增强）

| 场景 | 行为 |
| --- | --- |
| **有 JS** | `select` 的 `change` / chip 点击 → `fetch("POST", "/action/status")` 带 JSON → 返回 `{ok, level, counts}` → **原地**改该条目徽章配色与 `data-level`、更新顶部统计；**不刷新、不滚动** |
| **无 JS** | 表单照旧提交（`application/x-www-form-urlencoded`）→ 服务端 303 回首页，功能不缺 |
| 有 JS 时 | 隐藏兜底按钮；但按钮始终存在于 DOM（无 JS 环境仍可见可用） |

钩子：卡片 `data-point`/`data-level``，统计 `data-stat="<状态>"`，错误槽 `.inline-error`。

### 3. 失败原地提示

服务端 JSON 失败回 **400 + `{ok:false, message}`**（如「状态不合法：精通；只能是 学过/做过/输出/存疑」）。
前端把**下拉恢复成服务端仍认为的值**（`data-level`）+ 在卡片内红字显示 message——**界面状态不跳变**。
网络异常（fetch reject）同样恢复 + 提示「网络错误：状态没改动，请重试」。

### 4. HTTP 层

`handle_request` 增加 `body`/`content_type` 参数：
POST + JSON → `_handle_status_json`；POST + 表单 → `_handle_form_post`（303）；其它写方法照旧 405。
`do_POST` 改为把 body/Content-Type 透传（303 时补 `Location: /`）。

## 真实浏览器实测（Playwright + 系统 Chrome）

用 Playwright 驱动真实 Chrome（`channel: "chrome"`）跑了一遍，**抓到一个我实现时的偏离**：

### 偏离：chips 被我删掉了

任务卡验收标准写的是「点 **chip** 后 300ms 内变色」，但我实现 T-026「表单瘦身」时**把 chips 一并删了**，
只留下拉——结果 PANEL_JS 里还绑着 4 处 `.chip` 却页面上一个都没有（**死代码**）。
Playwright 脚本点不到 chip 才暴露出来。

**修法**：chips 恢复，并明确分工：

| 控件 | 角色 |
| --- | --- |
| chips（`.chip.js-only`） | **点一下即改**（JS 增强；无 JS 时不可见） |
| 下拉 + 保存按钮 | **无 JS 兜底**与精确选择（有 JS 时按钮隐藏，选完即提交） |

为此加了 `html.js` 标记与 `.js-only{display:none}` 规则：没 JS 时 chips 不显示，功能靠表单。

### 一处我差点误判的"bug"

最初脚本报「点 chip 后滚动从 1200 跳到 266」，看着像跳变。插桩后发现是
`focusin chip @scroll=266` —— **Playwright 点击前会先把元素滚入视口**（我的测试里把元素点到视口外了）。
改用「先把目标滚进视口再点」（等同于真实用户操作）后，滚动**完全不变**。
**是我的测试方法错了，不是代码问题**——这点我如实记下来，免得下次又被自己误导。
