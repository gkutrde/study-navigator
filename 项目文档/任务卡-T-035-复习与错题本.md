# 【T-035】 复习机制 + 错题本联动（F-15）

一张卡两件事，数据源都是既有文件。

## ① 复习题（间隔重复）

| 层 | 做法 |
| --- | --- |
| 字段 | 画像每个点加 `last_touched`（渲染成「— 最近：YYYY-MM-DD」，老画像缺省为空） |
| 刷新 | **distill 学到**、**done 回写**、**review 点评到** 时刷新 |
| 节奏 | `REVIEW_EVERY_NEW_TASKS = 3`：出满 3 道新题后第 4 道出复习题 |
| 挑点 | `pick_review_point`：只从「**学过**」且超期（默认 `DEFAULT_STALE_DAYS = 14`，可配）没碰的点里挑，越久越优先 |
| 标注 | 任务写 `**复习**：是` + 目标前缀「复习：」，看板画橙色「复习」角标 |
| 保底 | 复习题走模板（不调 LLM）——它本来就该是「把旧东西再做一遍」 |

## ② 薄弱点清单（错题本）

| 层 | 做法 |
| --- | --- |
| 产出 | review prompt 多问一段 `【问题点】`（短句，最多 3 条），解析后去重并入 `profile/weaknesses.md` |
| 注入 | 出题时（**题库匹配与 LLM 两条路径**）把清单注入 prompt：「这位学员反复出现这些问题点…」 |
| 移除 | `done` 涉及对应知识点时自动移除（用**解析后的点全名**匹配） |
| 展示 | 画像页出现「薄弱点清单」区块（空则不渲染） |

## 真机实测（验收 A/B/C）

| 项 | 结果 |
| --- | --- |
| **A** 连续出 4 题 | 前 3 题是新题；**第 4 题 = `复习：标题与段落标签`**（来自 30 天没碰的点），留档里有 `**复习**：是` |
| **B** 交一份有问题的作业 | 错题本从 0 条变 **3 条**（`缩进混乱 / 忘记给属性加引号 / 标签没闭合`，模型给了 4 条，按上限取 3）；下次出题 prompt **含全部 3 条** |
| **C** done 之后 | `标题与段落标签 缩进混乱` **被移除**，无关的 3 条保留；该点 `last_touched` 刷新为今天 |
| **D** 全量测试 | 见「完成结论」 |

## 途中修掉的真问题（都是真机/测试抓出来的）

1. **`mark_done` 把 last_touched 抹掉了** —— 它重建 KnowledgePoint 时没带上该字段，回写一次时间戳就丢。
2. **`touch_points` 匹配不上缩略名** —— 用户写「列表」、画像里是「列表（ul/ol/li）」；用精确 `find` 匹配不到。
   改成先走 `_resolve_point_index` 解析出真实点名。
3. **出题就刷新 last_touched 是错的** —— 起初按「任务用到了这个点」刷新，结果 LLM 每次把**全部**已掌握点写进 skills，
   每出一次题所有点都变成今天 → **复习队列永远挑不出超期点**（真机第 4 题仍出新题）。
   语义修正：只有真的「学习了/复习了」（distill / done）才算碰到，**出题本身不算**。
4. **`_run_next` 把 tasks_path 传成 None** —— 复习分支要求真实留档路径，传 None 就永远不会触发（连出 4 题全是新题）。
5. **CLI 的 done 没移除薄弱点**（只有看板路径有）；**CLI 的 next 没加载错题本**。两条都补齐，让 CLI 与看板等价。
6. **review 没开 with_problems** —— 解析函数写好了却没接线，错题本一直是空的。
