# 模块-书籍蒸馏导入

## 1. 职责与边界

### 模块职责

读取客户手工放入 `books/` 目录的 DeepSeek 蒸馏稿（markdown），调用 LLM 将其结构化为知识地图 `profile/syllabus.md`：书名 → 章节 → 知识点清单。

### 不负责什么

- 不做扫描、OCR、蒸馏本身（客户自行用 DeepSeek 完成后放入 `books/`）。
- 不维护「学过/做过/存疑」状态（那是 [[模块-知识画像]] 的事；地图只描述「书里有什么」，不描述「我会不会」）。
- 不保存书籍原文段落到地图（只保留知识点名称清单）。

### 上下游关系

| 方向 | 模块/系统 | 交换内容 | 约定 |
| --- | --- | --- | --- |
| 输入 | 本地 `books/` | 蒸馏稿 markdown | 文件顶部 frontmatter 必含 `book: 书名`；由客户手工放入 |
| 输入 | LLM API | 蒸馏稿内容 + 结构化 prompt | 发送内容不含凭证 |
| 输出 | `profile/syllabus.md` | 知识地图 | 写入先临时后替换；供 [[模块-任务生成]] 读取 |

## 3. 核心流程

### 流程： 导入一份蒸馏稿

1. 读取指定蒸馏稿，校验 frontmatter 含书名；缺失则报错指出缺什么，不导入。
2. 把蒸馏稿内容发给 LLM，要求输出 章节 → 知识点 的结构化清单（只要知识点名称，不要原文）。
3. 解析输出，合并进 `profile/syllabus.md`（同书名覆盖该书旧条目，不动其他书）。
4. 先写临时文件，成功后才替换；任何失败保留旧地图。

## 5. 状态、错误与排查

| 状态/错误码 | 触发条件 | 用户可见结果 | 系统行为 | 优先排查位置 | 是否可重试 |
| --- | --- | --- | --- | --- | --- |
| 格式不符 | 缺 frontmatter 书名 | 报错指出缺什么 | 不导入 | 蒸馏稿文件头 | 修复后重试 |
| LLM 接口失败 | 网络/额度错误 | 报错，提示地图未变 | 保留旧地图 | LLM 额度与网络 | 是 |
| LLM 输出不可解析 | 返回非约定格式 | 报错并提示重试 | 保留旧地图 | 结构化 prompt | 是 |

## 6.5 分块提炼策略（T-010 实测选定）

蒸馏稿单文件 **67K~129K 字符**（82~187 KB）。一次调用塞整本会有两个问题：
超出可控上下文、且质量下降。因此 `import` 按下面的方式分块：

| 项 | 约定 |
| --- | --- |
| 切分依据 | 按 **`##` 二级标题**切；若该级别不存在，自动退到最浅的标题级别 |
| 分块上限 | `DEFAULT_CHUNK_CHARS = 30000` 字符 |
| 为什么是 30000 | 实测蒸馏稿的二级节最大 16.7K 字符，取 30K 可让**绝大多数章节不被硬切**（保住章节语义）；7 本书的总调用数 60 → **25** |
| 单节超限 | 硬切成 `max_chars` 大小的片（保底，避免某块过大） |
| 不丢内容 | 所有块拼起来等于原文（只差块间空白） |
| 逐块调用 | 每块一次 LLM 调用，提示里标明「这是第 i/n 个片段，只需覆盖本片段出现的章节」 |
| 合并 | 按**首次出现顺序**排章节；同名章节合并、知识点去重保序（`merge_chapters`） |
| 进度 | CLI 逐块打印「正在提炼第 i/n 块…」（长稿不再黑屏 100 秒） |

> [!warning] 不要退回"整本一次调用"
> 早期实现是 `body[:20000]` 硬截断 —— 129K 的稿子会被**砍掉 5/6**且不报错。
> 现有回归测试 `test_build_import_messages_uses_given_chunk_fully` 锁住这一点。

## 6.6 格式校验（T-010）

`validate_distillate` 在动手前校验，**不合约定直接报错指出缺什么**，地图不变：

| 情况 | 报错要点 |
| --- | --- |
| 文件为空 | 「缺书名 frontmatter，也缺正文」 |
| 没有 frontmatter | 「缺 frontmatter：文件必须以 --- 开头，并在里面写书名」 |
| frontmatter 里没有书名 | 「缺书名：请加一行 title: 书名（也接受 book: 或 书名:）」 |
| frontmatter 之后没内容 | 「正文是空的：frontmatter 之后没有任何内容」 |

书名键接受 `title` / `书名` / `book`（实测这 7 份稿子用的是 `book:`）。

## 6.7 参考文本定位（T-022 实测）

`explain` 要拿"某知识点所属章节的参考文本"。优先级与三条实测约定：

| 项 | 约定 |
| --- | --- |
| 优先级 | ① `books/_src/<前缀>.txt` 的**原文**（按蒸馏稿标题里的行号区间截取）② 蒸馏稿里那一章的正文 |
| 行号口径 | 1-based，与 `books/_src/README.md` 一致（`read` 显示的行号） |
| 区间写法 | 实测四种：`（1266–2881）` 纯数字、`（L3990–4252）`、`（L69–L212）`、`（L2748–L8603）✅`；正则统一支持，并要求行号 ≥2 位以免把 `（第 1–11 章）` 当区间 |
| 章名匹配 | 先比名字；**中英不一致**（地图「第 1 章 认识 HTML」vs 蒸馏稿「第 1 章 · getting to know HTML」）时按**章号**兜底，并排除 `8.1` 这类小节标题 |
| 前缀怎么定 | 在蒸馏稿 frontmatter **显式声明** `source: <前缀>`（7 份已补）。按书名猜**不可靠**：实测覆盖率「C++ Primer」0.43、「鸟哥 Linux」**0.0**、「JS DOM 编程艺术」0.11；书名猜测仅作兜底 |
| 截断 | 单次送 LLM ≤ `MAX_REFERENCE_CHARS = 3000` 字符，超额截断并追加「（参考文本过长，已截断到前 3000 字符）」 |
| 不在地图 | 直接报错「不在地图里…不瞎编」，绝不猜 |

### 6.8 讲解缓存（T-024 M-03）

| 项 | 约定 |
| --- | --- |
| 位置 | `profile/explanations/<安全名>.md` |
| 内容 | frontmatter（point / book / chapter / origin）+ 正文讲解 |
| 命中 | 同名知识点第二次**零 LLM 调用**，输出标注「（来自缓存）」 |
| 刷新 | `explain <点> --refresh` 强制重生成并覆盖 |
| 名字安全 | 名字里的 `/ : * ?` 等被过滤成 `_`，过长或全被过滤时用 sha1 兜底——**不拼危险路径** |
| 写失败 | 缓存写不进去不影响本次返回（缓存是加分项） |

> [!warning] 素材坑（来自 `_src/README.md`，写在这里免得再踩）
> `cpp-primer-5e.toc.md` **缺第 10 章** → 章节骨架要用 `.index.md`；
> `head-first-html-css.index.md`（1 行）与 `acm-classic-2e.index.md`（88 字节）基本没有索引价值 → 这两本靠 `.toc.md`；
> `acm-classic-2e` / `cpp-primer-5e` / `head-first-html-css` / `nbird-linux` 的 `.code.md` 是空的（19 字节），代码要从 `.txt` 取。
