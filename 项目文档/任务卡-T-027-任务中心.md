# 【T-027】 任务中心（路由真分离 + 任务卡片）

## 取证（动手前）

四个路由 `""` / `index` / `knowledge` / `tasks` **返回完全相同的 12714 字符页面**，
`syllabus` 路由**压根不存在**；任务区是纯 markdown 渲染，没有结构化卡片。

## 修法

| 项 | 做法 |
| --- | --- |
| 路由分离 | `pages()` 拆成 `_home_page` / `_knowledge_page` / `_tasks_page` / `_syllabus_page`，四路由各自渲染 |
| 首页 | 只做概览（动作区 + 四态统计 + **最近一条任务**），不再倒出整份任务记录 |
| 导航 | 四链接 + 当前页高亮；画像页**无任务区块**，任务页**无画像区块** |
| 任务卡片 | 新增 `read_task_records` 把 tasks.md 解析成结构化 `TaskRecord`（时间/目标/出处/知识点/新点/步骤/验收） |
| 知识点 chips | 卡片上每个知识点一个 chip，点击 → `/action/explain` → **行内**展示（走 T-024 M-03 的缓存） |
| 删除 | 每卡一个删除按钮 → `delete_task`（白名单 `{when}`）→ `delete_task_record` 只删目标块（tmp + replace） |

### 顺带修掉的一处：JSON 分支只认 status

T-026 时 JSON 路径写死只在 `status` 上生效，别的动作一律走表单 → **303**。
JS 调 `explain`/`delete_task` 会拿到一个空 303。
改成 `_handle_action_json(action, body)` 通用分派：**所有动作都支持 JSON**，表单路径仍 303。

### 我实现时踩的两个坑（都由测试抓出来）

1. **把名称里的括号当注记剥了**：`_parse_record` 原用 `（[^（）]*）` 全删括号，
   `超链接 a 标签（href/target）` 被剥成 `超链接 a 标签`。改成只剥 `（本次…）` 这类后缀。
2. **测试断言太糙**：断言"画像页不含「任务中心」"，但顶栏导航里就有这四个字。
   改成断言 `<h2>任务中心</h2>` 与 `data-task=` 不出现。
