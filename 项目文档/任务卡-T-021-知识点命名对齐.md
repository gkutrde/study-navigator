# 【T-021】 知识点命名对齐

## 任务边界

- 所属模块：[[模块-书籍蒸馏导入]]、[[模块-任务生成]]
- 背景（T-010 实测）：地图 3168 个点（书里的细粒度名）与画像 26 个点（提炼出的概括名）**精确同名交集 0** →
  A-06 的「与画像最相关的书」全 0 命中 → 退回字典序第一本 → 提议 **main 函数**（C++ Primer 第 1 章）。
- 目标行为：用 LLM 把地图点对齐到画像的**既有概念**；对不上的标成新概念；对齐结果落盘并驱动选书/选点。
- 本任务不做：不改原始 syllabus.md、不改画像、不做人工映射界面。
- 前置依赖：T-010（已验收）。

## 为什么不能只靠文本匹配

| 方案 | 实测覆盖 | 问题 |
| --- | --- | --- |
| Latin token 交集 | **2.0%（70/3418）** | 误报严重：「HTML 简史」→「HTML 标签基础」、「XML 与 HTML 的关系」→「HTML 标签基础」 |
| CJK 整段匹配 | 极低 | 「标签与」≠「标签基础」，同义不同形 |
| **LLM 语义对齐** | **84% 给出映射** | 但置信度水分大，见下 |

## 对齐结果（真实数据，199.3s）

| 项 | 值 |
| --- | --- |
| 输入 | 地图 7 本书、3168 个去重点；画像 26 个概念 |
| 分批 | 每批 150 点（共 22 批） |
| LLM 给出映射 | 2653 / 3168 = **84%** |
| 标成新概念 | 515 个 |
| 置信度分布 | **high 350 / medium 1509 / low 1309** |
| 画像未变 / 地图未变 | 都是（对齐只写 alignment.json） |

### 关键发现：只信 high

抽查发现 medium/low 里大量硬凑：

| 地图点 | 被对到 | 置信度 | 判断 |
| --- | --- | --- | --- |
| h1 到 h6 六级标题 | 标题与文本格式化标签 | high | ✅ 正确 |
| ul 与 ol 列表 | 列表（ul/ol/li） | high | ✅ 正确 |
| img 标签与 src | 图片 img 标签（src/alt/宽高） | high | ✅ 正确 |
| 浏览器与服务器的工作原理 | 计算机网络 | low | ❌ 硬凑 |
| API 概念 / 速率限制 / Hacker News API | 计算机网络 | low | ❌ 硬凑 |

因此 `apply_alignment` 默认**只采用 high**（`trusted_only=True`）：
宁可少映射，也不要把错的说成对的。**high 350 条抽查全部正确**。

## 实测中发现并修掉的三个问题

| 编号 | 问题 | 修法 |
| --- | --- | --- |
| **G-1** | 书的**导读章**被当成知识点：选出的"下一个点"是「这本书的适用读者」「慢路与快路学习」 | 新增 `is_intro_chapter`（匹配 导读/前言/序言/intro/preface），选点时整章跳过 |
| **G-2** | 序言类条目混在正文里：`is_front_matter`（适用读者/学习原理/元认知/致谢/版权…） | 选点时跳过这类条目 |
| **G-3** | 选中书里高置信度点**全部已掌握**时，硬塞一个未映射的零碎条目（如「浏览器与服务器的工作原理」） | 该书没有"下一个该学的"就**按相关度跳下一本**（`_mapped_unmastered_in_book`） |

> [!note] 为什么"下一个未掌握点"要取映射后的概念名
> A-06 要求新点"来自地图"。对齐之后，地图坐标就是画像概念，两者终于在同一套名字上比较；
> 未映射的点保持原名（会被当成新概念）。这样 `generate_task` 的校验与 `next` 的提议才一致。
