# 学习领航员 需求与范围确认

> [!important] 开发前置条件
> 本文档的「目标、范围、验收标准、暂不做」必须与客户确认。任何一项含糊时，先列为待确认，暂不开始相关实现。

## 1. 背景与目标

### 客户要解决的问题

客户是大一计算机方向新生，习惯在飞书文档记录看视频/看书的笔记。问题：笔记基本是对着抄，代码「只会看、不会用」，知识停留在表面，没有转化为动手能力。缺一个能「读懂我的笔记 → 判断我会什么 → 安排下一步动手练」的闭环。

客户另有一类学习材料：扫描电子书。客户会自己用 DeepSeek 把电子书蒸馏成 markdown 笔记，希望这些蒸馏稿也能接入本工具，作为「要学什么」的路线参考。

### 本项目目标

做一个本地工具：读取客户飞书笔记（含子文档）与书籍蒸馏稿，维护「当前知识画像」（我会什么）和「知识地图」（这本书还有什么可学），并基于两者生成一个「现在就动手做」的小任务（写代码、跑起来），把「学过」推进到「用过」。做完后回写画像，形成 学 → 练 → 复盘 的循环。

两类输入的分工：**飞书笔记 = 学习轨迹的证据（我接触过什么）**；**书籍蒸馏稿 = 知识地图（这本书还有什么该学）**。两者不混用。

### 成功标准

- 工具能读出一篇指定飞书笔记（含其子文档）的正文内容，并提炼出其中涉及的知识点清单。
- 工具能把一份书籍蒸馏稿转为结构化知识地图（章节 → 知识点清单）。
- 给定画像 + 知识地图，工具生成的下一步任务满足：只用已学知识 + 最多一个新知识点（优先从知识地图中按书序选取）、可在 1~3 小时内完成、产出可运行的代码。
- 客户演示一个完整闭环：读笔记 → 生成任务 → 做完 → 画像更新。

### 明确不做

- 不做对飞书文档的**写操作**（本期只读）。
- 不做扫描、OCR 与电子书蒸馏的自动化——蒸馏由客户自行用 DeepSeek 完成，工具只消费蒸馏产出的 markdown。
- 不做笔记本身的管理/编辑功能（飞书就是笔记工具，不重复造）。
- 不做多人/团队协作功能。
- 看板（F-06）网页交互仅限固定动作集：触发 sync/distill/next/done、手工改知识点状态；**不提供自由命令执行入口**、不做登录鉴权、不绑定非 localhost 地址。任务代码始终由客户自己写，网页不代写。
- 不做多用户与对外分享部署：本工具为单用户自用；想给别人用 = 分享代码仓库，由对方配自己的飞书应用与登录态，不共享运行实例。
- 不直接解析 epub：原书统一用 Calibre 转为 txt 放 `books/_src/`（客户的蒸馏流程已有此环节）；工具只读 txt/markdown。不向 LLM 发送整书内容。
- 不评估非编程类笔记（高数、英语等只记录不生成编码任务）。
- 不把笔记正文、蒸馏稿原文、App Secret、笔记截图写入知识库或代码仓库。

## 4. 核心使用流程

### 场景： 一次「学 → 练」循环

1. 客户在飞书写完一篇笔记（如「Python 列表与字典」）。
2. 客户运行同步命令，工具把该文档（及其子文档）正文拉取为本地 markdown。
3. 工具调用 LLM 提炼笔记中的知识点，更新知识画像。
4. 客户运行「下一步」命令，工具结合画像与知识地图生成一个动手任务（如：写一个通讯录小程序，必须用列表+字典，验收标准是能增删查并保存到文件）。
5. 客户自己写代码完成任务（写代码的是客户，不是工具）。
6. 客户运行回写命令，画像更新为「做过」，闭环完成。

### 场景： 接入一本书的蒸馏稿

1. 客户自行用 DeepSeek 把扫描电子书蒸馏为 markdown（工具不参与此步）。
2. 客户把蒸馏稿放进 `books/` 目录（文件名即书名）。
3. 客户运行导入命令，工具调用 LLM 把蒸馏稿转为结构化知识地图（章节 → 知识点清单），写入 `profile/syllabus.md`。
4. 之后 `next` 出题时，新知识点优先从知识地图中按章节顺序选取「画像里还没有的下一个点」。

### 异常流程

| 情况 | 用户会看到什么 | 系统如何处理 | 是否需要人工介入 |
| --- | --- | --- | --- |
| 飞书凭证无效/过期 | 明确报错：凭证问题，提示检查环境变量 | 中止，不产出半成品文件 | 是 |
| 文档不存在或无权限（含子文档） | 报错并列出文档 ID，跳过无权子文档继续其余 | 已成功的部分保留 | 是 |
| LLM 接口失败 | 报错并保留原始文件 | 画像/地图不更新（保持上一版本） | 否，重试即可 |
| 笔记不含编程内容 | 提示「本篇无可提炼的编程知识点」 | 画像不变 | 否 |
| 蒸馏稿格式不符约定 | 报错指出缺什么（如缺书名 frontmatter） | 不导入 | 是 |

## 6. 非功能要求

- 使用环境：客户本机（Windows），命令行使用；开发/执行可借助用户的 Ubuntu VM（见全局规则）。
- 客户语言背景：Python 为主力（出题默认语言），正在学 C++，前端仅 HTML/CSS 基础——出题与示例代码据此选语言。
- 性能要求：单次同步 + 提炼在 1 分钟内完成（LLM 网络时延除外）。
- 安全与隐私：App Secret、LLM API Key 只存在于本地 `.env`；笔记原文、蒸馏稿原文不进 git 仓库、不进项目文档。
- 稳定性要求：任一外部接口失败不得损坏已有画像/地图文件（先写临时文件再替换）。
- 交付形态：源码 + 使用说明（README），命令行运行。
