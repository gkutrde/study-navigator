# 模块-任务生成

## 1. 职责与边界

### 模块职责

读取 `profile/knowledge.md`（我会什么）与 `profile/syllabus.md`（书还有什么该学），调用 LLM 生成一个「现在就动手做」的任务：只用已学知识点 + 至多一个新知识点（优先取地图中按章节顺序的下一个未掌握点），预计 1~3 小时完成，产出可运行代码，并给出明确验收方式。默认使用 Python（客户主力语言）；仅当画像中已有 C++ 相关知识点时才出 C++ 任务。

### 不负责什么

- 不替客户写任务代码（写代码的是客户本人）。
- 不维护知识点状态（回写由 [[模块-知识画像]] 的 done 流程完成，本模块只触发）。
- 不做难度自适应算法（本期靠 prompt 约束，N-02 后续再议）。

### 上下游关系

| 方向 | 模块/系统 | 交换内容 | 约定 |
| --- | --- | --- | --- |
| 输入 | 本地 `profile/knowledge.md` | 知识画像 | 由 [[模块-知识画像]] 维护 |
| 输入 | 本地 `profile/syllabus.md` | 知识地图 | 由 [[模块-书籍蒸馏导入]] 维护；可不存在（则新点由 LLM 自定） |
| 输入 | LLM API | 画像 + 出题 prompt | prompt 强约束「只用已学知识 + ≤1 新点」 |
| 输出 | 命令行 stdout | 任务描述文本 | 含目标、使用的知识点、验收方式 |

## 3. 核心流程

### 流程： 生成一个任务

1. 读取画像；若知识点少于 3 个，提示客户先积累笔记，不出题。
2. 把画像（知识点+状态）与地图（章节→知识点，若存在）发给 LLM，要求输出：任务目标、涉及知识点清单（标注哪个是新点，新点优先取地图中按书序的下一个未掌握点）、步骤提示、验收方式（运行后能观察到什么）。
3. 校验输出中声明的知识点均在画像内（新点除外），否则重试一次；仍不符则报错不出题。
4. 打印任务；同时追加到 `profile/tasks.md` 留档。

## 5. 状态、错误与排查

| 状态/错误码 | 触发条件 | 用户可见结果 | 系统行为 | 优先排查位置 | 是否可重试 |
| --- | --- | --- | --- | --- | --- |
| 画像知识不足 | 知识点 < 3 | 提示先积累笔记 | 不出题，正常退出 | 画像文件 | 否 |
| 出题越界 | 声明知识点不在画像内（新点除外） | 报错 | 重试一次后放弃 | 出题 prompt | 是 |
| LLM 失败 | 网络/额度 | 报错 | 不写 tasks.md | LLM 配置 | 是 |

## 6.5 题库优先（T-020 / F-09）

出题顺序：**先匹配题库 → 命中即用 → 未命中回退 LLM**。

| 项 | 约定 |
| --- | --- |
| 题库文件 | `profile/assignments.md`，当前 15 条，格式见文件头部说明 |
| 条目字段 | `course`（出处课程）/ `tags`（知识点标签）/ `level` / `new_skill` + 目标/实现要点/验收方式 |
| 标签要求 | **必须是画像里真实存在的知识点名称**，否则永远命中不了（有测试校验） |
| 匹配优先级 | ① 至少命中 1 个已掌握标签 ② 标签不含画像未知点 ③ 新点最好是画像里已记过但未掌握的点 ④ 命中标签越多越好 ⑤ 不需要新点优先、入门优先 ⑥ 编号兜底保证稳定 |
| 命中后 | `skills` 只保留已掌握标签 → 天然满足 A-03 的越界约束；任务写明**题目出处**（课程 + 条目编号） |
| 未命中 | 回退到 LLM 现编（既有逻辑不变），任务不带出处 |
| 副作用 | 命中题库时**不调用 LLM**，因此 `next` 在**未配置任何 LLM 凭证**时也能出题（实测确认） |

## 6.6 避免重复出题（T-023 L-02）

题库是**确定性**的：画像不变时 `pick_assignment` 永远命中同一条 → `next` 会一直出同一题。
两条出题路径都补了去重：

| 路径 | 做法 |
| --- | --- |
| 题库命中 | `read_given_idents(tasks.md)` 读出已出过的条目编号，`pick_assignment(..., already_given=…)` 跳过它们；全出过则回退 LLM |
| LLM 现编 | `build_next_messages(..., recent_goals=…)` 把最近 5 个目标写进 prompt，并明确「已经出过这些任务，**不要重复**」 |

留档里的识别方式：出处行形如 `**题目出处**：哈佛 CS50（A-01 个人名片页） ｜ 来自题库` —— 从中正则取 `[A-Za-z]+-\d+`。

实测：连续两次 `next` 分别出「个人名片页（card.html）」与「语义化主页（home.html）」。

## 6.7 地图版出题：多书选点与 A-06（T-010 定稿）

| 项 | 约定 |
| --- | --- |
| 地图格式 | **markdown**（`## 书名` / `### 章` / `- 知识点`），一本书一节；`load_syllabus` 返回 **BookMap 列表** |
| 加载 | `cli._load_syllabus` 返回全部书（旧实现用 json 读 markdown，永远 None，导致 A-06 从未生效） |
| 选书 | `next_unmet_point_for_books`：优先选**书内知识点被画像掌握最多**的那本；平手按文件顺序；全不匹配则退回第一本 |
| 取点 | 选定书里**按章序**第一个未掌握点 |
| 校验 | 有地图时，任务的新点必须 == 该点；不符则重试一次后报错 |
| 题库交互 | 题库命中**也要过同一道校验**：条目的 new_skill 不符就换下一条，都换不到回退 LLM |

### 6.8 命名对齐（T-021）

地图用书里的细粒度名字、画像用提炼出的概括名，两者**精确同名交集 0**（T-010 实测），
于是"与画像最相关的书"永远选不出来。`align` 命令用 LLM 把地图点对齐到画像概念：

| 项 | 约定 |
| --- | --- |
| 命令 | `python -m src.cli align [--provider X]` |
| 输入 | 地图全部去重点 + 画像全部概念名 |
| 规则 | 每个地图点从**画像已有概念**里选最接近的一个；选不出填 null（= 新概念） |
| 防编造 | LLM 给的概念名必须精确存在于画像，否则**丢弃并标成 new** |
| 落盘 | `profile/alignment.json`（原子写），原始 syllabus.md 不动 |
| 批量 | 每批 150 点（3418 点约 23 批） |
| 使用时 | `next` 若发现 alignment.json，就用**对齐后的书**选书，返回**映射后的概念名**，这样 A-06 的比较落在同一套名字上 |

> [!note] A-06 的命名问题已由 T-021 解决
> 地图 3168 个点与画像 26 个点曾经**精确同名交集为 0**（地图「h1 到 h6 六级标题」vs 画像
> 「标题与文本格式化标签」），选书时命中全是 0 → 退回字典序第一本 → 提议「main 函数」。
> 现在跑 `align` 生成对齐后：HTML 书命中 10 个已掌握概念居首，提议变为 `label 标签`
> （画像里正是「存疑」）。**只信 high 置信度**（350 条抽查全对），medium/low 视为未映射。

### 6.9 选点时的两组过滤（T-021 实测新增）

| 过滤 | 作用 |
| --- | --- |
| `is_intro_chapter` | 跳过「Intro 导读 / 前言 / 序言」整章——书的第一章常是"怎么读这本书"，不是知识点 |
| `is_front_matter` | 跳过正文里的序言类条目（适用读者 / 学习原理 / 元认知 / 致谢 / 版权…） |
| 已学完的书让位 | 选中书里没有"已映射但未掌握"的点时，按相关度**跳下一本**，而不是硬塞一个未映射的零碎条目 |

## 7.1 出题约束与实测口径（T-005）

### 硬约束（prompt + 代码双重把关）

| 约束 | 实现方式 |
| --- | --- |
| 只用已掌握知识 | prompt 给「已掌握」与「仍存疑」两份清单，并要求 skills 只能来自已掌握 |
| ≤1 个新知识点 | prompt 限定；解析出的 `new_skill` 至多一个 |
| 新点取地图书序下一个 | 有地图时校验 `new_skill` 必须等于 `next_unmet_point()` 的结果，否则带提示重试 |
| 画像不足不出题 | **已掌握（学过/做过）** 少于 3 个就拒绝；「存疑」不计入已掌握 |
| 不替客户写代码 | prompt 明确要求只给目标与要点，代码由客户写 |
| 越界 | skills 里出现既不在画像、也未标为新点的知识点 → 带提示重试一次，仍越界则报错不出题、不留档 |

### 踩过的坑（真实调用才暴露）

- **模型会在 JSON 后继续写说明文字** → 解析不能要求「整段是合法 JSON」，改用 `raw_decode` 从第一个 `{` / `[` 取完整 JSON 值。
- **模型会照抄带主题的写法**（把「列表（Python 基础）」当知识点名）→ 比较前做名称归一化（去掉结尾「（主题）」），并在 prompt 里明确「只写知识点名称」。
- **「存疑」不能当已掌握**：真实画像可能整份都是存疑（笔记只有主题、无解释代码），此时必须拒绝出题而不是硬出。

## T-035 复习机制与错题本

- **复习节奏**：出满 `REVIEW_EVERY_NEW_TASKS=3` 道新题后，下一道出复习题（走模板不调 LLM）。
  **两个条件都要满足**：到节奏 + 有超期没碰的点（`last_touched` 早于 N 天，默认 14，`--stale-days` 可改）。
- **只有「学过」参与复习**；存疑的还没学会、做过/输出的刚练过。
- **时间戳刷新的时机**（真机实测后修正）：distill 学到 / done 回写 / review 点评到；
  **出题本身不算碰到**——否则 LLM 每次把全部已掌握点写进 skills，复习队列永远挑不出超期点（已踩）。
- **错题本注入**：`profile/weaknesses.md` 的条目会进出题 prompt，让任务优先练到反复犯的毛病；
  done 涉及到对应知识点时自动移除（名字要用**解析后的点全名**匹配）。
