# 【T-010】 import 命令（蒸馏稿 → 知识地图）

## 任务边界

- 所属模块：[[模块-书籍蒸馏导入]]
- 对应需求/验收：T-010 / A-05；「蒸馏稿 → syllabus.md 知识地图；格式不符时报错指出缺什么」
- 目标行为：把 `books/` 里的蒸馏稿导入为 `profile/syllabus.md`（书名 → 章节 → 知识点，**不含原文段落**）；长稿**分块提炼**；格式不符明确指出缺什么且不破坏既有地图。
- 前置依赖：T-003、T-008（约定：文件名即书名 + 顶部书名 frontmatter）。

## 复现与根因（可确认）

| 现状 | 后果 |
| --- | --- |
| `build_import_messages` 写死 `body[:20000]` | 单文件 67K~129K 字符，一次调用**砍掉 5/6 且不报错** |
| 无格式校验 | 缺书名的稿子靠文件名兜底，不报错 |

## 分块策略（实测选定）

| 项 | 值 |
| --- | --- |
| 切分 | 按 `##` 二级标题；该级别不存在时退到最浅标题级别 |
| 上限 | `DEFAULT_CHUNK_CHARS = 30000` 字符 |
| 依据 | 实测二级节最大 16.7K 字符 → 30K 可让绝大多数章节**不被硬切**；7 本书调用数 **60 → 25** |
| 单节超限 | 硬切成 max_chars 片（保底） |
| 不丢内容 | 所有块拼接 == 原文（只差块间空白） |
| 合并 | 章节按首次出现顺序；同名章节合并、知识点去重保序 |
| 进度 | 逐块打印「正在提炼第 i/n 块…」 |

### 实测中的失败与处置（如实记录）

1. **Kimi 登录态在第 6 本中途过期**（约 10 分钟寿命，总耗时 603s）→ 第 6 本第 3 块 401、第 7 本立即失败。
   - 失败处理**符合预期**：地图未被改动、错误信息指明「第 3/3 块」且给出重新 `/login` 的指引；
   - 处置：改用 DeepSeek 兜底重跑，2 本共 40s 完成。
   - 结论：**长批量导入应一本一条命令跑**（每次调用重新读凭证），不要一次进程导 7 本。
2. **测试污染真实地图**：早期的短稿测试没传 `syllabus_path`，往真实 `profile/syllabus.md` 写了一条 40 章「主题N」的假书。
   - 处置：已从地图移除；并给所有 `import_book` 测试补上 `syllabus_path=tmp`，杜绝再犯。

| 编号 | 问题 | 影响 | 修法 |
